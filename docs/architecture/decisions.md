# 아키텍처 결정 기록

모델이 바뀌어도 동일하게 적용되는 제품·하네스 차원의 결정만 둡니다. 일시적 상태·작업 내역은 두지 않습니다. 새 결정은 아래 표에 한 줄로 추가하고, 근거가 바뀌면 상태를 갱신합니다(삭제 대신 `철회됨` 표기).

| # | 결정 | 상태 | 근거 |

| 1 | Build 단일 개발 총괄, 중간 소유자 없음 | 유효 | 위임·병합 비용이 중간 계층의 이득을 상회. 2026-11-06 Lead 제거 |
| 2 | 위임 깊이 최대 2, 단 두 번째 단계는 Plan→Explore만 허용 (General/Explore는 말단) | 유효 | 깊은 체인의 컨텍스트 손실을 막으면서 Plan이 실제 코드를 조사하게 한다. 2026-11-09 깊이 1→2, 단일 간선으로 제한 |

| 6 | ~~Design은 독립 UX 판단·비평 담당, 이미지 입력 모델 배정~~ | 철회됨 (2026-11-08) | 동일 과업 비교에서 Design의 판단 우위가 확인되지 않았고 비용은 가장 높았음. UI 판단은 Build로 환원하고 결정론적 검사 + 선택적 독립 읽기 전용 검토로 대체(#14) |

| 8 | 완료 판정은 모델 자기평가와 분리 (실제 동작·화면·검사 근거 필수) | 유효 | 검사 없는 완료 주장은 미완료로 처리 |
| 9 | 새 필수 리뷰어·자동 병합 게이트·워크플로 엔진 추가 금지. 선택형 읽기 전용 리뷰·관찰은 허용 | 유효 | 절차를 강제하지 않되, 필요할 때 쓸 수 있는 도구는 미리 준비한다. Impeccable 훅은 프로젝트별 명시 선택 시에만. 세션 관찰·PR 리뷰는 읽기 전용·선택 실행 |
| 10 | KSI 전용 디자인 스킬 신규 제작 금지 | 유효 | 외부 검증 스킬(Impeccable 중심) + 실제 레퍼런스 조합 |
| 11 | UI 품질은 실제 사용자 과업·렌더·동작으로 판단; 중요한 불확실성이 남으면 독립 검토를 고려하고 최종 수용은 사람 | 유효 | Build가 검토 필요성과 후속 수정을 판단한다. 독립 검토는 상시 역할이 아니라 필요할 때의 읽기 전용 세션이다. V-suite 6/6은 한정된 결함 탐지 실험이다 |
| 12 | 렌더 실패 시 코드 독해로 화면 검증 완료 주장 금지 | 유효 | 목표·조건·실제 조작·미확인을 남기고 필요시 `docs/evidence-pack.md`를 활용한다. 증거 기록 자체는 제품 수용을 대신하지 않는다 |
| 13 | UI 구조·표현은 사용자 과업과 정보 성격에서 출발해 선택하고, 구현 후 같은 기준으로 재평가 | 유효 | 형태는 데이터 성격과 사용자 행동에서 출발하며, 판단 깊이는 작업 불확실성에 따른다. 구조가 틀리면 정보구조·레이아웃을 바꾸고, 디자인 시스템 일관성은 컨트롤·타이포·간격에서 유지 |
| 14 | UI 비평은 상시 에이전트가 아니라 Build의 판단 + 결정론적 검사 + 선택적 독립 읽기 전용 검토로 수행 | 유효 | Design 유무 A/B(2과업): 상시 제공 시 Build가 0/2회 호출, 강제 1회는 IA를 소폭 개선했으나 시간 2배. 검출기는 대비·타이포·오버플로·접근성은 잡지만 정렬 축·정보구조 적합성은 못 잡음. 외부 자산(Oil UI·Impeccable·Mobbin·oh-my-design)은 방향·레퍼런스용이며 판단을 대체하지 않음 |
| 15 | 지속 정본과 과업 계획을 분리하고, 구현 중 발견한 사실을 정본에 반영한다 | 유효 | 사전 완전 문서화는 구현·렌더 중 더 나은 방법을 놓친다. 계획은 짧게 시작해 갱신하고, 과업을 넘어 유효한 사실만 정본·결정 기록으로 승격한다. 승인 게이트·별도 추적기 없음 |
| 16 | 디자인 정본은 현재 유효한 시각 결정의 정본으로 두고, 화면별 상세·상태·조작은 경험 정본에 둔다 | 유효 | 시각 결정 일지나 기능별 DESIGN.md 강제가 아니다. 대표 화면 검증 후 채택 규칙을 확정·재사용하고, 시안·레퍼런스 존재는 구현 완료와 구분한다 |
| 17 | 외부 전문 스킬은 플러그인 실행이 아니라 고정 커밋 라이브러리로 보관하고 프로젝트별로 설치한다 | 유효 | Claude Code manifest·MCP는 OpenCode로 이식되지 않는다. SKILL.md만 Native 로더로 쓰고, 전역에 17종을 배치하지 않으며, 기존 파일은 덮어쓰지 않는다 |
| 18 | 공통 지침은 짧은 탐색 지도로 유지하고, 상세 지식은 프로젝트 정본·`bd prime`·스킬 설명으로 위임한다 | 유효 | 2026-11-08 압축: 공통 1,664→359 words, 프로젝트 813→225. 긴 지침은 자율 판단을 줄이고 컨텍스트를 소비한다. 중복 UI 스킬 사본도 제거 |
| 19 | Sleev는 선택형 컨텍스트 게이트웨이로 두고, 작업 상태·정본을 대체하지 않음 | 유효 | 이 Mac에서는 2026-11-08 `opencode-go` 경로에 연결해 왕복 확인. 다른 환경은 기본 비활성. 품질·비용 효과는 동일 과업 비교로 재측정. 자동 압축 에이전트·고정 호출 시점 없음 |
| 20 | Beads는 다단계·장기 작업의 기본 추적기, 단순 수정은 이슈 없이 진행 | 유효 | 작업 상태·의존성·재개를 한곳에 둔다. 완료 게이트가 아니며 계획·설계 권한은 Build/Plan에 남는다 |
| 21 | Oil UI는 프로젝트 전용 선택형 스킬로 유지하고 전역 배포하지 않는다. 기존 제품 개선은 Impeccable 단일 사본을 쓴다 | 유효 | 새 화면 방향 탐색과 기존 제품 개선의 역할을 나눈다. 두 스킬의 통제 비교는 미완료이며, 자동 선택 충돌은 문서로 좁힌다 |
| 22 | Plan은 실제 코드·프로젝트 증거에 기반하고, Build가 증거팩을 공급한다 | 유효 | 깊이 2의 Plan→Explore로 부족한 증거를 보완할 수 있다. 모델 강화보다 입력 근거의 정확성이 중요하다. Plan은 확인한 사실·가정·누락 증거를 구분하고 일회성 스크립트를 조사 대체로 쓰지 않는다. Native Plan system prompt는 덮어쓰지 않는다 |
