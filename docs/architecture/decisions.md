# 아키텍처 결정 기록

모델이 바뀌어도 동일하게 적용되는 제품·하네스 차원의 결정만 둡니다. 일시적 상태·작업 내역은 두지 않습니다. 새 결정은 아래 표에 한 줄로 추가하고, 근거가 바뀌면 상태를 갱신합니다(삭제 대신 `철회됨` 표기).

| # | 결정 | 상태 | 근거 |
| --- | --- | --- | --- |
| 1 | Build 단일 개발 총괄, 중간 소유자 없음 | 유효 | 위임·병합 비용이 중간 계층의 이득을 상회. 2026-11-06 Lead 제거 |
| 2 | 위임 깊이 최대 1 (자식은 말단, 추가 위임 금지) | 유효 | 깊은 체인의 컨텍스트 손실 방지. 병렬은 너비로 처리 |
| 3 | 공유 소스는 모델·도구를 고정하지 않음 | 유효 | 휴대용 기본값 유지. 선택은 설치본·문서의 권장값으로 |
| 4 | Plan은 자문 전용 (구현 승인 없음, Explore만 호출) | 유효 | 판단과 실행의 책임 분리. 작업 전 1회 자문은 선택 |
| 5 | General은 범위 한정 실행 (아키텍처·다모듈 통합 판단 제외) | 유효 | 소형 모델 운용 전제. 입력·범위·검사 기준을 함께 전달 |
| 6 | Design은 독립 UX 판단·비평 담당 (코드 수정·위임 금지), 이미지 입력 모델 배정 | 유효 | 판단과 제작의 책임 분리. 결함 탐지를 넘어 정보구조·사용 흐름 자체의 문제도 독립적으로 지적하고 구조적 개선을 제안할 수 있음. 중요한 문제 없으면 만들지 않고 통과 선언. 2026-11-06 신설, MiMo 고정(설치본 한정, V-suite 6/6 동점) |
| 7 | 병렬 구현은 worktree 분리, 통합·검증은 Build가 메인에서 수행 | 유효 | 파일 충돌 방지. worktree는 DB·포트·브라우저·OS를 격리하지 않음 |
| 8 | 완료 판정은 모델 자기평가와 분리 (실제 동작·화면·검사 근거 필수) | 유효 | 검사 없는 완료 주장은 미완료로 처리 |
| 9 | 새 필수 리뷰어·자동 게이트·워크플로 엔진 추가 금지 (최소 이벤트 연결은 허용) | 유효 | 절차가 아니라 증거로 품질을 확보. Impeccable 훅은 프로젝트별 명시 선택 시에만. 세션 완료·실패·중단 관찰 등 실제 필요한 최소 연결은 별도 구현 가능 |
| 10 | KSI 전용 디자인 스킬 신규 제작 금지 | 유효 | 외부 검증 스킬(Impeccable 중심) + 실제 레퍼런스 조합 |
| 11 | UI 품질 루프: Design이 동일 세션에서 직접 렌더를 관찰하고 결함 목록을 반환, Build/General이 구현, Build가 재검증, 최종 수용은 사람 | 유효 | 구현자≠시각 인수자. Design은 만족 선언까지 잔류, 미수용 항목은 이유 기록. V-suite 6/6·B 루프 3/3으로 검증 |
| 12 | 렌더 실패 시 코드 독해로 검증 완료 주장 금지, 증거팩 5항(목표·화면·조건·검증·Design 의견)으로만 인수 판단 | 유효 | `docs/evidence-pack.md`. Design 직접 관찰이 관찰 환경 문제였음이 V-suite 재실행으로 확인됨 |
