# 기능 목록과 세션 실행 증거

두 도구는 담당자가 **필요할 때만** 호출하는 보조 도구입니다. 등록 여부·도구 완료·명령 패턴은 실제 작업 성공이나 제품 인수를 뜻하지 않습니다. 설치와 확인은 [설치 안내](installation.md), 실제로 확인한 범위는 [검증](validation.md)을 따릅니다.

## 현재 위치의 기능 목록

`ksi_capabilities_inventory`는 호출 세션과 플러그인 위치가 일치하는지 확인한 뒤 선택한 영역의 목록을 반환합니다. 기본 영역은 `agent`, `skill`, `tool`, `plugin`이며, `mcp`는 상태 조회가 재연결에 미치는 영향을 확인하지 못했으므로 **명시 요청할 때만** 조회합니다.

위치 확인은 호출 시점의 검사이지 동시 세션 이동과 목록 조회 전체를 원자적으로 묶는 보장은 아닙니다. 이동 중에는 다시 호출해 확인합니다.

예를 들어 Native 도구에 `{ "domains": ["skill", "tool"], "locateSkills": ["impeccable"] }`를 전달할 수 있습니다. 반환하는 ID 수·길이는 제한하며 잘림과 미확인을 표시합니다. 지원하지 않는 형식은 해당 영역 전체가 미확인이 될 수도 있습니다. 스킬 위치는 등록된 경로 문자열의 `project-hint`/`external-hint`일 뿐, 심볼릭 링크·존재·읽기 권한을 확인한 결과가 아닙니다. 실제 스킬과 파일 접근은 기존 Native 스킬·읽기 도구의 권한을 따릅니다.

- 선택하지 않았거나 조회에 실패한 영역은 `unknown`이며, 목록에 등록됐다고 호출 권한이나 작동 성공이 보장되지는 않습니다.
- `plugin` 목록은 Native가 반환한 ID 그대로의 제한된 목록입니다. 격리 환경에서는 도구형 `opencode.*` ID도 포함됐으므로, 개수를 설치 패키지 수나 활성 판정으로 해석하지 않습니다.
- 출력에는 현재 프로젝트 디렉터리와 기능 ID가 포함됩니다. ID 문법 제한은 범용 비밀 탐지기가 아니며, 이름 자체에 민감한 정보가 들어갈 수 있으므로 공유 전 확인합니다. 전체 설정·설명·자격증명 값은 반환하도록 의도하지 않았습니다.
- 별도 CLI `node scripts/capabilities.mjs [directory] [--only agent,skill,mcp]`는 기존 관리용입니다. `--only`를 생략하면 MCP까지 조회하며, 이 CLI의 `opencode api`는 공유 서비스가 없으면 자동 기동할 수 있으므로 의도와 권한을 먼저 확인합니다. Native 도구의 사용을 위해 CLI를 실행할 필요는 없습니다.

## 호출 세션의 실행 증거

`session_evidence_summary`는 **호출 세션의 현재 컨텍스트**에서 관찰된 변경 후보와 그 뒤의 검증 후보·실패 단서·미완료를 개수로 요약합니다. 다른 세션 ID를 받지 않으며, 입력 원문·명령·파일 경로·임의 역할명을 결과에 싣지 않습니다. 요약을 위해 현재 컨텍스트의 도구 입력과 결과는 읽습니다. 세션 위치도 조회 전에 검사하지만 확인과 컨텍스트 조회 사이의 동시 이동까지 원자적으로 막지는 못합니다.

호출 시 컨텍스트 배열 `order`를 명시해야 합니다. 격리 OpenCode V2.2.0에서는 `ctx.session.context`가 `oldest-first`로 관찰됐습니다. 도구는 시간 단서를 함께 검사하며 순서를 확인할 수 없거나 선언과 충돌하면 `unknown`으로 남깁니다. 관련 이벤트의 시각이 같으면 가능한 순서를 최대 32개까지 비교하고, 결과가 달라지거나 한도를 넘으면 미확인으로 둡니다. 타임스탬프 일치는 동시 작업의 실제 완료 순서를 증명하지 않습니다. `includeVisual: true`는 시각 도구 완료 횟수를 추가할 뿐 화면을 보거나 판단하지 않습니다.

컴팩션·누락, 자식 세션, 감지하지 못한 셸 파일 변경과 동시 변경은 사각지대입니다. 처리 예산을 넘거나 필요한 정보가 없으면 요약 대신 `unknown`을 반환합니다. 분석 예산은 컨텍스트 API의 가져오기 비용 자체를 제한하지 않습니다. 검증 후보·도구 완료 또는 실패 **단서**는 독립적인 테스트 성공이나 실패 판정과 다릅니다. 실제 종료 결과·제품 동작·화면을 별도로 확인하세요.

기존 파일 기반 `node scripts/session-audit.mjs <session-json-file-or-directory> [--newest-first]`는 사용자가 지정한 스냅샷만 감사합니다. 기본은 입력 배열을 오래된 순서로 취급하며, 관찰한 V2 메시지 API 기본 응답처럼 최신순이면 `--newest-first`를 명시합니다. 입력 순서가 불명확하면 결과를 신뢰하지 않습니다. 이 CLI는 `global/plugins/ksi-session-evidence/core.mjs`를 공유하므로 배포할 때 함께 포함해야 합니다.
