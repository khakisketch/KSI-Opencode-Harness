# OpenCode Native Decision (선택형 소스 연결)

**승인된 방향 (2026-10-29):** Build와 Lead가 도구·스킬·위임 등 중요하고 불확실한 선택에서
Native Decision을 자동으로 보조받되, 매 판단마다 호출하지 않습니다. 결과는 참고일 뿐 권한이나
담당자의 판단을 대신하지 않습니다. 기존 제공자·데이터·권한 경계를 보존합니다. 승인된 방향과
구현·설치·실제 호출 성공은 별개이며, 아래는 기존에 관찰한 연결 상태입니다.

KSI 자체 `decision_evaluate` 플러그인은 운영에서 제거됐으며 복원하지 않습니다.
OpenCode가 제공하는 Decision API를 사용하는 얇은 보조 연결을 저장소에 추가했습니다. 이 문서는
**소스와 관찰된 한계**를 설명하며 전역 설치, 에이전트의 자발적 호출이나 운영 활성화를 뜻하지 않습니다.

## 저장소의 보조 연결

`global/plugins/ksi-native-decision/`은 기본 설정이 없는 상태에서는 호출을 전송하지 않습니다.
운영자가 허용한 위치·제공자·모델과 데이터 전송 동의가 별도로 일치하고 Native 권한이 허용된 경우에만
판단 API를 호출합니다. Build·Lead가 필요할 때 선택하는 참고 도구이며 결과로 행동을 자동 실행하지
않습니다. 세션별 시도 제한은 플러그인 재로드 시 초기화되고, 제공자의 내부 재시도나 과금 상한은 아닙니다.
서버 프로세스의 동의가 필요하므로 저장소를 내려받는 것만으로 켜지지 않습니다. 실제 제공자 성공이나
모델의 자발적 사용은 미확인입니다.

도구는 한 번에 **예/아니요 질문 하나**와 최소 맥락을 받고 보정되지 않은 확률을 돌려줍니다. 질문은
최대 600자, 맥락은 최대 1,800자입니다. 제공자·모델 ID는 각각 최대 128자이며 공백·`/`·`*`·`?`를
포함할 수 없으므로 이 조건에 맞지 않는 모델은 현재 연결로 쓸 수 없습니다.

### 설정 조건

사용자가 실제 위치에서 특정 Decision 제공자·모델에 자료를 보낼 것을 승인한 경우에만 운영자가 적용합니다.
도구 `ksi_native_decision`은 최소한의 질문과 맥락을 해당 제공자에 전달하며, 기존 모델 호출과 별도로
비용이 생길 수 있습니다. 비밀과 불필요한 저장소 내용을 넣지 마세요. 구성은 다음 모두가 필요합니다.

1. 사용하려는 모델은 OpenCode의 **Decision 모델**로 등록되어 있어야 합니다. 채팅 모델이나 모델 이름의
   존재만으로 이 API가 동작한다고 가정하지 않습니다. 제공자의 이용 권한과 데이터·비용 정책을 확인합니다.
   자동 발견 경로 밖의 운영자 관리 플러그인 경로를 지정하고, **기존 설정을 보존해 병합**합니다.
   아래는 자리표시자이며 설치 명령이나 전체 설정 파일이 아닙니다. 자동 발견 경로와 명시적 경로에 같은
   플러그인을 중복 배치하지 마세요.

   ```jsonc
   {
     "plugins": [{
       "package": "/absolute/path/to/KSI-Opencode-Harness/global/plugins/ksi-native-decision",
       "options": {
         "enabled": true,
         "allowDataTransfer": true,
         "model": { "providerID": "PROVIDER_ID", "id": "DECISION_MODEL_ID" }
       }
     }]
   }
   ```

   예시처럼 신뢰하는 복제본을 직접 참조할 수 있습니다. 해당 경로의 파일이 바뀌면 이후 로딩되는 코드도
   바뀔 수 있으므로 운영자가 그 경로를 관리해야 합니다.

2. **서버 프로세스의 운영자 관리 환경** `KSI_NATIVE_DECISION_CONSENT`에 실제 프로젝트의 정규
   절대 경로와 위 제공자·모델을 정확히 일치시켜 넣습니다. 다중 프로젝트는 각각 동의 항목이 필요합니다.

   ```json
   [{"directory":"/absolute/canonical/project","providerID":"PROVIDER_ID","id":"DECISION_MODEL_ID","allowDataTransfer":true}]
   ```

   예를 들어 해당 값과 플러그인 설정을 준비한 뒤, 사용자가 직접 아래처럼 개인 OpenCode 서버를 시작할
   수 있습니다. 자리표시자는 실제 승인한 경로와 모델로 바꿉니다. `--standalone`은 개인 서버 선택이지
   OS 네트워크나 파일시스템 격리를 뜻하지 않습니다.

   ```sh
   KSI_NATIVE_DECISION_CONSENT='[{"directory":"/absolute/canonical/project","providerID":"PROVIDER_ID","id":"DECISION_MODEL_ID","allowDataTransfer":true}]' opencode --standalone /absolute/canonical/project
   ```

3. 호출마다 기존 Native `decision.evaluate` 권한을 확인합니다. 명시적 거부는 유지되고, Native 기본
   정책이 매번 승인창을 표시한다고 가정하지 않습니다. 위치·동의·권한 중 하나라도 맞지 않으면 제공자를
   호출하지 않습니다. 일반 셸이나 CLI로 이를 우회하지 않습니다.

도구는 한 플러그인 인스턴스에서 세션당 최대 세 번 생성을 시도하고, 15초 후 대기를 중단합니다.
플러그인 재로드 시 한도는 초기화되므로 과금 상한은 아닙니다. 권한 대기 취소 뒤 승인창이 남을 수 있고,
이미 제공자에 전송한 자료를 되돌리거나 처리·과금 중지를 보장할 수 없습니다. 동의와 위치의 재확인도
전송과 원자적이지 않습니다. 이 도구가 모든 비밀을 자동으로 알아내거나 제거하는 것은 아닙니다. 서버
환경값은 같은 서버 프로세스에 접근할 수 있는 악성 코드에 대한 격리 경계도 아닙니다. 현재 터미널의
환경변수를 바꿔도 실행 중인 공유 서버에는 자동 반영되지 않으며, 이 작업에서 공유 서비스나
자격증명을 변경하거나 재시작하지 않았습니다.

## 현재 확인된 경로

OpenCode V2는 별도 세션을 만들지 않고 입력에 대해 구조화된 판단을 요청하는 실험적
`experimental.generate.decisions` API를 제공합니다. 서버 API의 경로는
`POST /api/experimental/generate/decisions`입니다. 요청한 모델에 입력이 전달되므로 제공자와
모델에 따라 외부 전송·과금이 생길 수 있습니다. 이 API는 호출할 때 동의를 받거나 KSI 도구의
호출별 권한·한도를 자동으로 대신해 주지 않습니다. 모델 목록 등록만으로 사용 성공은 보장되지 않습니다.

2026-10-29 조사 당시 해당 위치·세션에서 조회한 도구 목록에는 에이전트가 직접 호출할 수 있는
Native Decision 전용 도구가 보이지 않았습니다. **API가 존재한다는 사실과 Build·Lead가 안전하게 이를
자발적으로 호출한다는 사실은 다릅니다.** 당시 위치·세션의 제한된 조회 결과이며 다른 버전이나 세션까지
단정하지 않습니다. 격리 scripted Build는 기존 Native 셸과 OpenCode CLI를 통해 API를 호출했으나,
이는 자발적 선택이나 실제 사용의 증거가 아닙니다. 기존 `decision.evaluate` 권한·호출 한도는 이
일반 셸 경로에 자동 적용되지 않습니다. 또한 CLI `--data`에 넣은 입력은 실행 중 프로세스 인자로 보일 수
있습니다. 동의와 권한 경계가 확인되기 전에는 이를 자동 사용하거나 우회하도록 지시하지 않습니다.

## 검증과 한계

- **격리 관찰 (OpenCode 2.2.1, 2026-10-29):** 별도 HOME·합성 프로젝트·소유 서버에서 KSI Decision
  플러그인 없이 Native HTTP API가 loopback 가짜 System One 응답을 받아 구조화된 결과로 반환했습니다.
  별도 scripted Build는 Native 셸과 CLI로 같은 API를 호출해 가짜 응답을 받았습니다. 합성 입력·가짜 모델이며
  실제 제공자 성공, 모델 품질, 에이전트의 자율 호출 또는 운영 안전성을 증명하지 않습니다.
- **새 소스 연결:** 별도 격리 Native 서버에서 scripted Build와 그가 위임한 합성 Lead가 각각 보조 도구를
  호출해 가짜 Decision 제공자의 응답을 받았습니다. 같은 시험에서 권한 거부·위치 동의 부재는 가짜
  제공자에 요청하지 않았습니다. 취소·동의 철회 및 뒤늦은 권한 승인 사례는 모의 SDK로만 확인했습니다.
  scripted 호출은 실제 모델의 자발적 선택이나 실제 제공자 성공이 아닙니다.
- **이전 운영 관찰 (2026-10-28):** 당시 공유 서버에서 승인된 합성 질문으로 Jev Native 직접 호출 1회가
  HTTP 400이었습니다. 원인과 현재 성공 여부는 미확인입니다. 과거 다른 격리 서버의 성공이나 현재 목록이
  이를 해결했다는 뜻은 아닙니다.
- Decision은 목표 사용 여부뿐 아니라 도구·스킬·위임 등 불확실한 선택의 판단 참고 자료로 검토합니다.
  매번 호출할 필요는 없고 결과가 기존 지침·권한이나 담당자의 판단을 대신하지 않습니다. 테스트 성공·
  화면 품질·사용자 수용이나 권한을 증명하지 않으며, 모델 오류·취소·근거 부족을 부정 응답이나 성공으로
  바꾸지 않습니다. 이는 활용 방향이지 연결이 설치·활성화됐다는 뜻은 아닙니다.

실제 제공자 사용이나 공유 서비스 설정을 변경할 때는 데이터 범위·권한·비용과 적용 범위를 먼저 확인합니다.
실제 제공자로 Build·Lead에서 동작하는지는 아직 미확인입니다. 사용자는 별도의
Decision 엔진을 되살리는 대신 Native API에 연결하는 방향을 승인했습니다. 그 승인과 특정 제공자에
프로젝트 자료를 전송할 동의, 실제 설치·활성은 구분합니다.
