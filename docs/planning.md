# 증거 기반 계획 (Evidence-grounded planning)

Plan은 자문 역할입니다. 이 문서는 Build가 Plan에 넘길 **증거팩**과 Plan이 돌려줄 **계획의 형식**을 정의합니다. 필수 승인 단계나 별도 문서 세트가 아니며, 작업 계획은 짧고 일회성입니다.

## 언제 Plan을 쓰는가

- 신규 기능, 아키텍처·데이터 계약 변경, 원인 불명의 반복 실패.
- 여러 모듈·화면·데이터에 걸친 큰 변경.
- UI/UX 구조를 크게 바꾸는 작업.
- 구현 방향·대안·위험이 아직 열려 있는 작업.

명확한 로컬 수정, 이미 정해진 패턴의 재사용, 문구·수치 변경에는 쓰지 않습니다.

## 증거팩 (Build가 준비)

Plan을 호출하기 전에 Build는 다음을 모읍니다. 모든 항목이 항상 필요한 것은 아니지만, **모르는 것은 모른다고 명시**합니다.

1. 목표와 수용 기준.
2. 관련 파일 경로·핵심 라인, 현재 diff, 주변 구현 패턴.
3. 프로젝트 정본·계약·ADR 중 이번 변경을 제한하는 것.
4. 이미 실행한 명령, 테스트, 빌드, 브라우저/런타임 결과와 실패 로그.
5. 실제 데이터 형태·API 응답·스키마 증거.
6. 미확인 사항과 Plan이 판단해 주길 원하는 결정.
7. 권한·데이터 정책·호환성·시간 같은 제약.

증거를 못 모았으면 빈칸을 추측으로 채우지 말고 “미확인”으로 남깁니다.

## Plan의 출력

1. **확인한 사실** — 파일·명령·런타임 증거 참조.
2. **가정과 미확인** — 확인하지 못한 것.
3. **누락된 증거** — Build가 추가로 읽거나 실행할 정확한 파일·명령.
4. **대안과 trade-off** — 실행 가능한 선택지와 포기하는 것.
5. **권장 순서** — 의존성, 체크포인트, 가장 작은 다음 행동.
6. **검증** — 실제 동작·렌더·테스트로 어떻게 증명할지, 롤백 방법.
7. **위험** — 일회성 도구, 마이그레이션, 호환성, 범위 확장.

계획은 Build가 소유합니다. Plan의 제안은 결정이 아니며, Build가 증거와 제품 목적에 비추어 채택·수정·거부합니다.

## 안티패턴

- 저장소를 읽지 않고 내장 지식으로 API·데이터 형태·프로젝트 동작을 단정.
- 실제 코드·테스트 대신 일회성 스크립트를 먼저 작성.
- 파일 참조도 검증 방법도 없는 일반론적 계획.
- Plan을 승인 게이트·두 번째 트래커·영구 문서로 만드는 것.
- 깊이 2의 유일한 예외(Plan→Explore)를 무시하고 Explore/General이 하위 에이전트를 부를 것처럼 가정.

## 깊이 2, 단일 간선

Build는 root(깊이 0)이고, 자식은 Plan/General/Explore(깊이 1)입니다. 깊이 2는 **Plan → Explore 한 간선만** 허용합니다.

- **Build**: Plan/General/Explore를 직접 호출합니다.
- **Plan**: 증거가 부족하면 Explore를 호출할 수 있습니다. General이나 다른 Plan은 호출하지 않습니다.
- **Explore**: 읽기 전용 말단입니다. Plan/General/Explore를 호출하지 않습니다.
- **General**: 실행 말단입니다. Plan/Explore/General을 호출하지 않습니다.

Plan은 Explore를 쓸 수 있어도 증거팩을 대체하지 않습니다. Build가 제공한 사실과 Explore가 확인한 사실을 구분하고, 확인하지 못한 것은 가정으로 남깁니다. Root Plan 세션도 같은 규칙을 따릅니다.

## 짧은 예시

```text
목표: 두 시점 비교 화면에서 사용자가 변화량과 신뢰도를 빠르게 판단하게 한다.
수용: A/B 선택, 비교 결과, 로딩·빈·오류 상태, 4개 뷰포트.
증거: AnalysisPreviousResultCompare.tsx, previous-result-compare.ts,
      관련 테스트, 실제 스키마, 현재 스크린샷.
미확인: 비교 기준 선택이 결과에 미치는 영향, 대용량 관측에서의 지연.
질문: 정보 우선순위와 비교 기준 UI를 어떤 구조로 가져갈지.
```
