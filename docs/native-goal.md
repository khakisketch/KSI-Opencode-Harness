# OpenCode Native Goal

**승인된 방향 (2026-10-29):** Lead에 맡기는 작업에는 Native Goal을 기본으로 시작하고,
Goal 상태와 막힘을 Build에 전달하도록 연결합니다. 별도의 Goal 엔진을 새로 만드는 대신 Native를
사용하며, 추가 평가에 시간과 비용이 들 수 있습니다. 아래 관찰은 기존 동작의 기록이며, 자동 연결의
실제 구현·설치 상태는 이 문서의 최신 검증 결과와 설치 상태를 따릅니다.

Build의 현재 세션에서는 평소 일반 요청을 사용하며, 여러 차례 구현·확인이 필요한 긴 작업에는
OpenCode의 내장 목표를 별도로 선택할 수 있습니다. 이 저장소는 별도의 GOAL 엔진이나
컨트롤러를 설치하지 않습니다. 사용 전 해당 OpenCode 버전의 명령 사용 가능 여부와 모델·데이터·비용
정책을 확인하세요. 목표에 승인된 범위, 보존할 것, 확인할 결과와 막혔을 때 보고할 사항을 함께 쓰세요.

```text
/goal 승인된 범위에서 기능을 구현하고 실제 동작과 오류를 확인해줘. 기존 데이터를 보존하고 막히면 보고해줘.
/goal pause
/goal resume
/goal clear
```

명령은 목표가 있는 **같은 세션**에서 사용합니다. `pause`는 목표를 일시정지하고,
`resume`은 정지된 목표의 반복을 다시 시작하며, `clear`는 목표를 제거합니다. `/goal`만 입력하면
설정된 목표가 있을 때 상태와 사용법을, 없으면 사용법을 안내합니다. 명령 응답은 오류 형식일 수 있습니다.
진행 중인 실행을 즉시 중단해야 한다면 클라이언트의 중단 기능도
사용하고 상태를 확인하세요. 중단과 목표 삭제는 다릅니다. 새로운 목표 입력은 기존 목표를 대체할 수
있으므로 주의하세요. 지원 여부·표시는 클라이언트와 버전에 따라 확인이 필요합니다.

## Lead 연결의 현재 상태

- **자동 시작은 아직 미구현입니다.** OpenCode 2.2.1의 Native `subagent`가 자식을 만들고 첫 요청을
  내부에서 시작합니다. 노출된 연결점에서 그 사이에 정확한 자식의 `/goal`만 안전하게 시작할 수 있는
  방법을 아직 찾지 못했습니다. 첫 요청이 접수된 뒤의 모델 context hook도 별도 확인했지만, 기존 Goal
  확인과 새 Goal 생성이 원자적이지 않아 다른 목표를 덮어쓸 수 있고, 취소와 경합하면 kickoff가 자식을
  다시 깨울 수 있습니다. `queue`는 순서를 제어할 뿐 깨우기를 막지 않습니다. 목표가 시작된 것처럼
  위장하거나 이런 경합을 감수하는 자동 주입을 설치하지 않습니다.
- **상태 전달은 부분 구현입니다.** 저장소의 `global/plugins/ksi-native-lead-goal/`은 Native Goal
  상태를 읽어 새 Lead 또는 기존 Lead를 이어서 호출한 **전경** 위임 결과에 덧붙이는 연결입니다. 부모와
  자식의 관계 및 Lead 역할을 확인한 뒤 당시 상태와 길이를 제한한 사유를 전달합니다. Goal을 시작·재개·
  수정하지 않습니다. 목표가 없거나 읽을 수 없는 경우를 완료와 구분하며, 상태는 조회 시점의 스냅샷이고
  사유는 신뢰할 수 없는 내용입니다. 그 상태 역시 과업 검증이 아닙니다.
- 이 연결은 내려받기만으로 전역에 설치 또는 활성화되지 않습니다. 특히 백그라운드 완료 알림에 Goal
  상태가 자동으로 붙는다고 가정하지 마세요.
- **집중 확인:** 격리 OpenCode 2.2.1에서 시험 드라이버가 기다리는 자식에 Goal을 수동 주입하고 합성
  평가자가 `blocked`를 반환하게 했을 때, Native `paused` 상태와 사유가 새 위임과 이어서 호출한 위임의
  결과에 전달됐습니다. 자동 시작이나 실제 모델 품질의 확인이 아닙니다. `complete` 전달은 합성 단위
  자료로만 확인했습니다. [검증](validation.md)

상태 전달만 따로 사용하기로 한 경우에는 운영자 관리 경로의 이 플러그인을 기존 OpenCode V2 `plugins`
설정에 추가할 수 있습니다. 예를 들어 복제본을 신뢰하고 직접 관리한다면 `"plugins":
["/absolute/path/to/KSI-Opencode-Harness/global/plugins/ksi-native-lead-goal"]`처럼 명시적 경로
하나로 불러올 수 있습니다. 격리 시험도 명시적 경로를 사용했습니다. 기존 배열을 덮어쓰거나 자동 발견
경로에 같은 플러그인을 중복 배치하지 마세요. 이것을 불러와도 Goal은 자동 시작되지 않으며, 공유 실행
환경에 적용할지는 별도로 결정합니다.

## 역할과 경계

Build는 전체 목표·위임·통합·최종 인수를, Lead는 배정된 결과의 반복 구현·교정·검증을,
General은 분리된 실행을 맡습니다. OpenCode 2.2.1의 목표는 세션별이며 자식이나 fork에 자동
상속되지 않습니다. Build는 목표와 제약을 위임 내용에 명시해야 합니다. 위임문에 `/goal`을 적는 것만으로
자식 명령이 실행되지는 않습니다. Build 목표가 Lead에 자동 활성화되거나 부모와 자식 목표가 자동으로
결합된다고 약속하지 않습니다. 자식 목표를 시험 드라이버가 명시적으로 시작한 사례는 아래와 같지만,
에이전트가 안전하게 자동 시작·연결하는 운영 경로는 아직 검증하지 않았습니다. 승인 없는 자식 목표 생성,
권한·모델 변경, 새 외부 서비스 호출은 이 안내가 허가하지 않습니다.

목표 반복과 평가에는 추가 모델 호출·시간·비용이 발생할 수 있고 재개는 반복 예산을 새로 시작합니다.
의미 없는 반복, 실패, 권한 문제 또는 범위 밖의 필요가 보이면 일시정지하고 원인을 확인하세요.
지침은 모델 행동을 강제하지 않습니다. 자식 위임 도구의 `completed`는 자식 Goal의 완료·막힘 사유를
증명하지 않습니다. 자식 Goal 상태가 중요하지만 확인되지 않았다면 미확인으로 남기고, 상태와 별도로 실제
과업 결과·검사·막힌 점을 살펴봅니다. Native의 완료 표시도 독립적인 검사 성공 증명이 아니며, 기능 확인과
실제 화면·사용자 수용도 별개입니다. Build는 실제 결과와 실패·미확인을 통합해 보고해야 합니다.

## 확인한 것과 확인하지 못한 것

- **저장소 소스:** `global/AGENTS.md`와 `global/agents/lead.md`는 위 운영을 안내합니다. 저장소 변경만으로
  다른 환경에 설치되는 것은 아닙니다. 기존 설정을 보존하는 수동 병합 절차는 [설치 안내](installation.md)를 따르세요.
- **후속 지침 전달:** 별도 격리 서버의 scripted Build에 공통 지침 전체, scripted Lead에 공통·Lead 지침
  전체가 전달됐습니다. 지침 이해·준수, 자식 상태 자동 전달이나 실모델 개선의 증거는 아닙니다.
- **시험 호스트의 전역 파일 (2026-10-29):** 이전 목표 안내를 공통·Lead 지침에 병합하고 당시 소스 일치와
  격리 scripted 입력 전달을 확인했습니다. 이후 자식 Goal 상태를 구분하는 안내는 **저장소 소스에만**
  추가했으며 전역에 다시 병합하지 않았습니다. 다른 세션의 반영·실모델 준수도 보장하지 않습니다.
- **격리 관찰 (2.2.1, 2026-10-29):** 별도 HOME·합성 프로젝트·loopback scripted 모델에서 내장 명령의
  생성·일시정지·재개·삭제, 사용자 중단, 반복 정체 및 부모 소유 백그라운드 자식 대기를 관찰했습니다.
  실패 명령 뒤에도 의도적으로 `done`을 반환한 평가자는 목표를 완료시켰고, after 훅 예외도 거짓 완료
  보고를 막지 못했습니다. 별도 합성 사례에서 시험 드라이버가 Lead의 첫 요청 시작 후 자식 Goal을 명시
  주입하자 전경 부모는 평가를 기다렸습니다. 자식 Goal이 `blocked`로 정지한 사례에서도 부모의 위임 도구는
  `completed`였고 막힘 사유는 자동 전달되지 않았습니다. 모델 품질 측정이나 실제 사용자 작업의 증거는 아닙니다.
- **미확인:** 실제 모델·설치된 하네스의 작동, 모든 클라이언트의 중단 표시, 자식 목표의 안전한 자동
  시작과 백그라운드 상태 전달, 실제 모델에서의 상태 전달, 독립적 강제 검증 게이트 및 UI/사용자 수용.
  검증 게이트 실험은 합성 증거 모델일 뿐 실제 hard gate가 아닙니다.

버전별 동작은 [2.2.1 내장 소스](https://github.com/anomalyco/opencode/blob/v2.2.1/packages/core/src/plugin/goal.ts)를
참고하세요. 이후 버전이나 설치 상태를 이 기록으로 추정하지 않습니다.
