## Interpretation review focus

1. Bounded API/download repair: Developer can own investigation/implementation/self-tests;
   no mandatory Plan, busy-Build prerequisite or user-authored task form.
2. Tightly coupled judgment or trivial integration: Build may work directly; no quota or
   forced task splitting, and "integration" is not permission to bypass visual ownership.
3. Worker success/partial result: inspect actual code and independent integrated checks,
   not prose/toast/test subset as completion; later edits need affected verification.
4. Worker interruption/repeated mismatch: preserve work, concrete diagnosis/feedback and
   adapt scope/path; no blind respawn/replay, implicit installs/model changes or endless loop.
5. Shared files/parallel work: sequential handoff by default; concurrent writers require
   separate workspaces and disjoint ownership, not a second simultaneous Primary.
6. Small visual repair or unavailable design: remains design-owned; no Developer/Build
   visual fallback, new direction, external delivery or implicit goal authorization.
