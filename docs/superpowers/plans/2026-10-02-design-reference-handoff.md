- Existing tokens, components and human-approved direction override references. Missing reference capability is reported honestly but is not automatically a design blocker; missing required design capability must not be silently replaced by a UI-reference skill.
- Handoff ties human direction approval to the actual required-file content snapshot, not only a success status, mutable URL or manifest schema version. Missing/unread/truncated required assets are disclosed/resolved before implementation.
- Build owns product implementation/API/data/Git/server verification. Design feedback may return as questions/findings; automatic outer-session launches, recursive generation and two writers in product files are not authorized.
- Design preview verifies direction/prototype states, not real authentication/API/routing/permissions. Product server verifies implementation. Give reachable labeled links and report actual inspected states; do not imply localhost refers to the user's PC.
- Installer still writes only three roles. This is guidance/explicit handoff, not automatic enforcement or proof of sandbox isolation, token/cost savings, visual quality or end-to-end behavior.
