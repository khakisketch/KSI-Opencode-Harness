# 오프라인 UX 비교 보조

이 선택형 도구는 **호출자가 직접 작성한 JSON 한 건**의 비교 조건과 사용자 피드백·참고 판단·에이전트 판단 차이를 정리합니다. 화면을 실행·캡처하거나 receipt·출처를 검증하지 않고, 모델에 연락하거나 품질 PASS를 만들지 않습니다. Muse·Terra나 하네스가 더 나았는지도 판정하지 않습니다. `declared-aligned-unverified`는 입력 문자열의 일치일 뿐입니다. 생략한 조건, 선택 편향, 다른 검토자나 실제 환경이 비교를 무효화할 수 있으므로 사람이 원본 증거를 확인해야 합니다.

## 사용

시각 검토 패킷이나 실제 사용자 의견이 있다면 허용된 범위에서 과업·조건·유지할 장점·반증을 확인하고 **민감정보를 제거한 요약 기록을 직접 작성**합니다. 실제 사용자 피드백이 없으면 `unknown`으로 둡니다. 원본 패킷, 비밀정보·개인정보·운영 데이터·원시 로그·이미지를 그대로 넣지 않습니다. 자료를 파일 경로로 가리켜도 도구가 읽거나 검증하지 않습니다.

하네스 저장소에서 예시를 확인하거나, 검토한 자신의 기록을 표준 입력으로 전달합니다.

```sh
node scripts/ux-evaluation.mjs < tests/fixtures/ux-evaluation-synthetic.json
node --test tests/ux-evaluation.test.mjs
```

fixture와 그 피드백은 전부 합성이며 실제 모델 결과·캡처·사람 판단이 아닙니다. 도구는 Node.js 외 의존성 없이 **stdin만 읽고 stdout만 출력**하며, 모델·네트워크 호출이나 자동 파일 생성을 하지 않습니다. 인자에 파일명·외부 참조·명령·출력 경로를 받지 않습니다. 입력은 최대 65,536바이트이며 잘못된 입력에서는 일반 오류만 출력하고 보고서를 만들지 않습니다.

출력 리디렉션은 도구가 아니라 셸이 처리합니다. 검증 전에도 파일이 생성·잘릴 수 있으므로 기존 작업을 덮어쓰지 않는 경로를 직접 선택하세요. 터미널 기록·표준 출력·파이프·저장된 보고서에는 내용이 남을 수 있습니다. 자동 익명화나 비밀 탐지는 없으며, 출력 안의 문장은 권한이나 명령이 아닌 신뢰할 수 없는 데이터입니다.

## 기록 형식

실행 가능한 예시는 합성 fixture를 참고하세요. 최상위에는 `task`, `request`, `baseline`, `candidate`, `issues`가 있습니다. 두 비교 대상 객체는 필수이고, 각 객체의 `name`, `conditions`, `provenance`, `minutes`, `cost`, `costUnit`, `iterations`는 선택입니다. 조건은 `scenario`, `state`, `viewport`, `inputs`, `environment` 문자열 또는 null입니다. 조건 일치는 필요조건이지 충분조건이 아닙니다. `provenance`는 호출자의 선언이며 캡처·receipt의 증명이 아닙니다. 소요 분·비용과 단위·반복 수를 알 때만 기록하고 모르면 null로 둡니다. 단위가 다르면 비용을 동등하게 비교하지 마세요. 도구는 예산을 강제하거나 반복 실행하지 않습니다.

`issues`는 최대 50개 항목의 필수 배열입니다. 각 항목에는 `topic`, `preserve`, `counterevidence`, `userFeedback`, `referenceJudgment`, `agentJudgment`를 넣을 수 있습니다. 좋아한 부분과 중요한 반증을 따로 남깁니다. 판단값은 `positive`, `negative`, `mixed`, `unknown` 또는 null/생략입니다. `userFeedback`은 실제 사용자가 명시한 의견에만 쓰고, `referenceJudgment`는 별도로 제공한 참고 판단이지 자동 정답이 아닙니다. `agentJudgment`는 에이전트의 주장입니다. 이 값의 진위·출처도 도구가 인증하지 않습니다. 판단 비교는 문자의 일치 여부일 뿐 의미를 해석하지 않습니다.

문자열은 최대 500자이고 제어문자·알 수 없는 필드·잘못된 수·음수나 1,000,000 초과 수·정수가 아닌 반복 수는 거부합니다. 코드처럼 보이는 일반 문자열도 실행하지 않습니다.

## 결과 해석과 한계

조건이 다르면 `not-comparable`, 조건이나 과업·요청·대상 이름이 빠지면 `unknown`, 모두 입력되고 조건 문자열이 같으면 `declared-aligned-unverified`입니다. 상태나 의견의 일치는 품질·사용자 승인 판정이 아닙니다. 누락된 조건, 거짓 주장, JSON의 중복 키, 바뀐 사용자 필요, 어댑터의 실제 화면 관찰 여부는 탐지하지 못합니다. 의견 차이는 점수·순위·인과관계 없이 `yes`/`no`/`unknown`으로만 나타냅니다.

허용된 검토자가 원래 승인 과업·독립 사용자 피드백·실제 렌더 증거를 별도로 볼 수 있어야 합니다. 이 보고서는 그 증거의 대체물이 아니라 색인입니다. 모델·하네스 비교는 과업·상태·환경·입력·예산·검토 방식을 통제하고 반복과 실패를 모두 기록해야 하며, 고른 예시 하나로 일반적 효과를 주장하지 않습니다.
