# Native OpenCode V2 architecture

KSI now has two parts: three custom role templates and a standalone installer. The installer renders ordinary V2 `agents/*.md` files into a selected configuration directory. OpenCode reads those files natively; there is no distributed KSI `setup(ctx)`, `agent.transform`, or KSI entry in `plugins`. [OpenCode agents](https://opencode.ai/v2/docs/agents) and [configuration](https://opencode.ai/v2/docs/config) define the runtime semantics.

OpenCode's built-in Build and Plan are the Primaries. OpenCode's built-in Explore and the installed Developer, Test Runner, and Reviewer are Subagents. Build/Plan/Explore retain their built-in system prompts. Build may work directly or delegate as appropriate; the default Developer cannot delegate. There is no KSI design primary role.

Design is a separate workspace, not an OpenCode role. Material product, visual, and interaction design happens in [OpenDesign](integrations/opendesign.md); Build keeps small established-pattern UI edits, production integration, and the engineering judgment to notice when a change is material enough to need design work. This installer distributes no design skills, craft references, or design-system package: OpenCode does not compose OpenDesign's craft metadata, and the project's own tokens and Human-approved direction remain authoritative. This adds no orchestrator role, no KSI preview runtime, no mandatory design stage, and no model override.

Each installed custom role owns its description, mode, system prompt, and narrow native permissions. The bundle has no skill whitelist and omits model/variant/steps so existing user settings remain in their native configuration layer. The installer does not parse or rewrite JSONC and refuses differing file collisions without explicit replacement and backup. A collision in a *different* config layer still requires effective-config inspection; file checks alone do not settle OpenCode precedence. OpenCode's last matching permission rule wins, and its permissions are not an OS sandbox.

No slash command is installed. The former six `ksi_*` evidence tools, output archive, runtime delegation/signature checks, helper lifecycle guard, and continuity hooks are not part of the installer distribution. Agents can use normal authorized OpenCode tools and optional shared `AGENTS.md` guidance, but this is guidance, not the same enforcement or telemetry. The approved product milestone still needs Human end-to-end acceptance; package tests alone do not establish it.

The installer never removes a previously installed role. An earlier global installation may still contain `agents/design.md` and the retired design skills; retiring them is a separate, reviewed migration step in the target configuration directory, not a side effect of this package. See [installation and migration](../INSTALL.md).

OpenChamber is a client: managed mode uses its managed OpenCode server's configuration, external-server mode uses the external server's configuration. OpenChamber's orchestration tool is managed-only. Neither UI mode has been accepted from the local package checks.
