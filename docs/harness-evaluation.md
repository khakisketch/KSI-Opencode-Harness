# 하네스의 실제 과업 평가

역할·권한·설치·도구 검사는 필요한 기반이지만 사용자 경험의 개선을 증명하지 않습니다.
이 문서는 비교 방법이며 결과 보고서나 새로운 제품 목표 정본이 아닙니다.

## 비교 조건

- 현재 OpenCode와 개선 OpenCode는 같은 기준 코드·승인된 미커밋 변경·모델·추론 수준·예산·권한으로 새 세션에서 비교합니다.
- Codex 비교도 같은 기준과 요청을 사용하되 모델·도구·서버 측 조건을 맞출 수 없는 차이를 명시합니다. 이름이 같은 모델만으로 동일 조건이라 하지 않습니다.
- 각 실행은 독립된 작업본·로컬 테스트 데이터·포트·증거 위치를 사용합니다. 앞선 후보의 수정 결과를 다음 후보의 출발점으로 쓰지 않습니다.
- 시작 전에 사용자 과업·보존 조건·검증법을 정하고 실패·중단·시간 초과도 남깁니다. 좋은 사례만 고르지 않습니다.
- 모델 변경, 위임 정책, 시각 도구 수정, 압축 설정은 가능한 한 따로 비교합니다. 현재 제품이나 운영 DB를 실험 대상으로 자동 선택하지 않습니다.
- 실제 실행 역할·모델·추론 수준과 신규/재사용 자식을 구분합니다. 분석 모드의 비구현을 개발 실패로 세거나, 기존 자식의 저장 모델을 새 설정으로 간주하지 않습니다. 저렴한 Build 직접 실행과 Plan 자문 후 Build 실행을 비교할 때에는 전달·통합·검토·재작업 비용도 포함합니다.
- 한도·인증·접속·권한 차단은 구현 실패와 별도 기록합니다. 차단 사례를 숨기지 않되, 도구·제공자가 작업을 시작하지 못한 결과를 모델의 코딩 능력 점수로 사용하지 않습니다.

## 대표 과업

| 유형 | 한 번의 요청에 포함할 결과 | 관찰할 실패 |
| --- | --- | --- |
| 버그 수정 | 재현 → 수정 → 관련 회귀 및 원래 재현 확인 | 설명이나 첫 수정 뒤 조기 종료 |
| 기능 개발 | 주요 사용자 흐름·권한·재시도·기존 데이터 보존까지 연결 | 하위 작업 완료를 전체 완료로 오인 |
| UI 단순화 | 채택한 방향으로 수정하고 실제 데스크톱·모바일 화면과 주요 행동 확인 | 사용자가 거부한 카드·설명을 다시 추가 |
| 병행 변경 | 다른 변경 보존, 독립 작업 진행, 통합 직전 재대조 | 무조건 중단·덮어쓰기·미커밋 기준 누락 |
| 이어가기 | 위임 또는 압축 뒤 목표·정정·미완료를 유지하고 재개 | 같은 요구 재질문·진행 상태 초기화 |
| 도구 복구 | 승인된 외부 합성 캡처 검토, 불허 파일은 거부 | 반복 실패·경계 우회·영수증 없는 검토를 영수증으로 표시 |
| 위임 결과 인수 | 자식의 부분 완료·부정확한 완료 보고를 실제 동작과 대조 | 자식 검사만 통과하고 전체 사용자 흐름은 실패했는데 종료 |
| 중단과 교체 | background·중첩 작업을 중단하고 부분 변경을 보존 | 늦은 완료 보고를 현재 결과로 채택하거나 살아 있는 자식과 대체 작업이 동시 수정 |

## 보존 회귀 평가

하네스 개선은 새로 성공한 과업만으로 채택하지 않는다. 지침 압축, 모델 교체, Beads·Sleev·도구 추가 전후에 같은 V-suite를 실행해 기존 성공의 손실을 함께 본다. 배경 연구는 자동 하네스 개선에서 평균 점수가 올라도 기존 통과 과업이 손실되고, 비용이 늘며, 다른 과업으로의 일반화가 균일하지 않음을 보고한다(arXiv:2611.07624).

- **기준선:** 변경 전에 통과했던 대표 과업과 각 과업의 통과 조건·증거·필수 보존 여부를 고정한다.
- **사후 실행:** 같은 코드 기준·모델·추론 수준·권한·예산·요청으로 새 세션에서 다시 실행한다. 후보의 결과를 다음 후보의 출발점으로 쓰지 않는다.
- **과업별 비교:** 신규 성공, 유지, 회귀(이전 통과가 실패), 차단, 미검증을 각각 기록한다. 평균 점수 상승이 회귀를 가리지 않게 한다.
- **비용:** 시간, 토큰·과금, 재작업, 사용자 개입을 전후로 기록한다. 평균 상승이 비용 증가나 필수 과업 손실을 정당화하지 않는다.
- **채택 규칙:** 필수 보존 과업의 회귀가 있으면 채택하지 않는다. 의도적 손실은 결정 기록에 명시하고 대체 증거를 남긴다.
- **일반화:** 한 제품·한 과업의 성공을 다른 제품으로 일반화하지 않는다. V-suite 밖의 결과는 미검증으로 표시한다.

V-suite는 동일 조건에서 반복하는 고정 대표 과업 묶음이다. 현재 6개 UI 결함 탐지 실험과 7/7 기계 검사는 서로 다른 증거이며, 하네스 전체 V-suite 기준선은 아직 없다. 별도 자동 하네스 최적화 시스템이나 점수 최대화 루프는 두지 않는다. 채택은 기록된 증거를 보고 Build와 사용자가 판단한다.

## 올바른 평가기의 조건

- 일반 과업은 직접·위임·혼합 구현 모두 성공할 수 있습니다. 작성 주체·자식 수는 관측값이지 통과 조건이 아닙니다. 명시적으로 위임 능력을 시험하는 과업과 분리합니다.
- 기억 회상·행동 재개·실제 검사 완료를 따로 판정합니다. 완료 표식의 등장, 실행 약속, `running` 도구는 검사 성공이 아닙니다. 상태 반전·미확정 후보 누락·보존 제약 위반을 음성 사례로 포함합니다.
- 압축·이어가기 시험에서 원래 요구를 재주입해 정답을 공급하지 않습니다. 최신 정정만 전달하는 경우도 포함하고, 기존 제약·거부 방향·미확정 사항이 유지되는지 관측합니다.
- 실행 중이거나 실패한 변경 가능 작업은 이전 검사 결과의 신선도를 보장하지 않습니다. 메시지 순서·페이지 범위·현재 API로 관측할 수 없는 정보는 미확인으로 남깁니다.
- 실제 과업의 성공을 scripted 모델의 정해진 경로로 대체하지 않습니다. 기계적 전달 시험은 유지하되, 자발적 도구 선택·복구·인수 판단은 별도 과업으로 봅니다.

## 결과 기록

기존 검증 문서나 비공개 실행 기록에 아래 항목만 간결하게 남깁니다. 새로운 전역 제품 원장을 만들지 않습니다.

1. **조건:** 코드 기준과 로컬 변경 식별, 실제 모델·추론 수준, 실행 환경과 예산, 비교 불가능한 차이.
2. **결과:** 완료 조건별 실제 구현·검증·미검증·차단. 테스트 성공과 제품 수용은 구분.
3. **사용자 부담:** 재촉, 같은 설명 반복, 방향 정정, 불필요한 확인 질문 횟수. 정당한 권한·제품 결정 질문은 따로 분류.
4. **복구와 보존:** 도구 실패/충돌 뒤 진행, 승인 범위·기존 작업·거부한 방향 유지 여부.
5. **비용:** 첫 검토 가능한 결과까지의 시간, 총 시간, 토큰/과금과 단위, 검토·재작업 비용. 모르면 unknown.

먼저 요구 충족과 안전을 통과해야 합니다. 자식 수·호출 수·테스트 수가 줄었다는 이유만으로 우수하다고 판정하지 않습니다.
소수의 합성 사례는 일반적인 Codex 대비 우위나 실제 제품 품질의 증거가 아닙니다.

기존 검증 문서나 허용된 비공개 기록이면 충분하며 전용 JSON 도구를 요구하지 않습니다.
실모델 실행은 별도 사용량을 소비하며 승인된 제공자·자료 범위 안에서만 수행합니다.
