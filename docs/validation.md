# 검증 및 적용 범위

기존 브라우저·소스 검사 검증 기록은 2026-10-15 기준 OpenCode **2.0.29 / Linux arm64**에서 확인한 내용입니다. 능력 연결 진단은 2026-10-16에 추가했습니다. 다른 운영체제는 확인하지 않았습니다.

## 능력 연결 진단

필요한 역할·스킬이 없거나 도구 연결이 의심될 때만 실행합니다. 개발의 필수 단계가 아닙니다.

```sh
node scripts/capabilities.mjs
node scripts/capabilities.mjs /path/to/project
```

기존 인증을 사용하는 `opencode api get`으로 Native의 에이전트·개발 스킬 등록과 Context7·Mobbin 연결 상태를 조회하고, 로컬 CLI의 PATH 존재 여부를 확인합니다. 설치·설정 변경·인증·모델 호출·자동 재시도는 하지 않습니다. OpenCode CLI 자체가 필요시 관리 서비스를 시작할 수는 있습니다. 큰 CLI 응답의 파이프 잘림을 피하기 위해 전용 임시 파일로 받아 읽고 정리하며, 응답 원문·오류 원문·설정·토큰은 출력하지 않습니다.

등록은 에이전트별 권한·스킬 자동 노출·실제 실행 성공을 보장하지 않습니다. PATH 존재는 CLI 동작 검증이 아닙니다. 선택 도구의 부재는 실패로 간주하지 않으며, API 조회 실패는 미확인으로 구분합니다. 브라우저 연결·제품 데이터 접근·렌더·모델 품질은 이 명령으로 검사하지 않습니다.

진단기의 응답 처리·출력 제한 회귀 검사는 `node --test tests/capabilities.test.mjs`로 실행합니다. 이 검사는 모의 응답을 사용하며 실제 연결을 입증하지 않습니다.

2026-10-16 로컬 실행에서는 추적 대상 역할 5개·스킬 8개 등록, Context7·Mobbin 연결, Node·Playwright CLI·GitHub CLI의 PATH 존재를 확인했습니다. 진단기 검사 20개와 기존 검사 61개가 통과했습니다. 실제 제품 작업이나 장시간 완주를 평가한 결과는 아닙니다.

지식 부족은 공식 자료·사례·스킬, 관찰 부족은 실제 화면·로그·데이터 접근, 실행 부족은 환경·도구·권한, 판단 부족은 전문 역할·독립 검토를 우선 검토합니다. 모델 변경은 실제 과제의 근거와 비용을 확인한 뒤 결정합니다. 이번 진단은 제품 완주 효과 평가가 아닙니다.

## 브라우저 검증 경로

- 연결된 데스크톱에서는 Native Browser를 우선합니다. 분리된 자식 세션, SSH·헤드리스 환경, 반복 자동화에는 기존 Playwright CLI를 사용합니다.
- 도구가 없다고 판단하기 전에 Code Mode 카탈로그에서 필요한 기능을 검색합니다. Native는 `browser.snapshot`으로 요소 ref를 얻고, `browser.tabs.focus`로 탭을 선택한 뒤 보이는 창에서 캡처합니다. DOM/접근성 탐색과 캡처 가능 여부는 별개이며, 이 가시성 조건은 헤드리스 CLI의 요구사항이 아닙니다.
- 캡처가 실패하면 원인에 맞는 허용된 대안을 시도하고 남은 제약을 보고합니다. 담당자가 직접 검수하며, 일반적인 방법 선택·화면 탐색을 사용자에게 넘기거나 코드 분석만으로 시각 검증을 완료했다고 하지 않습니다. 필요한 인증·권한·제품 결정은 사용자에게 요청합니다.
- CLI는 고유한 작업별 세션 이름으로 실행하고 자신이 만든 세션만 종료합니다. 전체 정리용 `close-all`·`kill-all`은 사용하지 않습니다.
- 프로젝트의 Playwright Test, 감사 스크립트, 기존 캡처·로그를 보존하고 산출물 위치·보고 규칙을 따릅니다. 프로젝트 초기화나 테스트 의존성 교체를 하지 않습니다.
- Playwright MCP와 `agent-browser`는 기본 구성에서 제거했습니다. 기존 CLI·Chrome·원본 `playwright-cli` 스킬을 재사용하고, CLI가 없을 때만 공식 `@playwright/cli@0.1.22` 설치를 검토합니다.

해당 환경에서는 Native Browser로 외부 페이지 열기·캡처·기본 클릭을 확인했습니다. 전역 Playwright MCP를 비활성화한 뒤 Design Specialist 자식 세션에서 CLI 0.1.22를 `DISPLAY`·`WAYLAND_DISPLAY` 없이 실행해 외부 화면, 로컬 상태 전환, PNG 3개 읽기를 확인했습니다. 자식 세션이 끝난 뒤 별도 보호 세션도 유지됐습니다. 이는 브라우저 경로 확인이지 실제 제품 UI의 품질 검증은 아니며, 다른 OS나 전체 원격 SSH 환경의 검증을 의미하지 않습니다.

## 디자인 판단의 적용 범위

중요한 UI 작업은 구현과 병행해 뒤늦게 검수하는 대신, 영향받는 구조·핵심 조작을 정하기 전에 전문 역할이 사용자 과업·사용 조건·기존 화면을 파악합니다. 중요한 미해결 설계 문제는 관련 화면·상호작용과 필요한 스킬로 검토하되, 기존 유효 근거를 재사용하고 매 수정마다 외부 조사·와이어프레임·별도 승인을 요구하지 않습니다.

Native의 스킬 등록·설명 노출은 본문 로드·적용과 다릅니다. 자식 specialist는 설정 모델을 사용하지만, primary 역할 선택만으로 기존 세션 모델이 바뀌지는 않습니다. 이번 보정은 모델 설정을 바꾸지 않습니다. [공식 Skills](https://opencode.ai/v2/docs/skills) · [공식 Agents](https://opencode.ai/v2/docs/agents)

효과 관찰은 추후 실제 제품 작업에서 별도 조사·설계 지시 없이 판단이 시작됐는지, 관찰·근거·선택이 연결됐는지, 담당자가 실제 화면을 검수하고 문제를 먼저 수정했는지 확인합니다. 현재는 지침 적용과 Native 인식만 확인하며, 제품 작업 관찰은 유보한 상태입니다. 등록 진단·회귀 검사 통과는 이 행동이나 디자인 품질의 증거가 아닙니다.

## UI 소스 검사기

전역 Native V2 플러그인 `ksi.impeccable-detector`는 성공한 `write`·`edit`·`patch` 뒤 세션 디렉터리 안의 변경된 UI 파일을 제한적으로 검사하고 기존 도구 결과에 요약을 추가합니다. 자동 수정, 모델 재호출, 검사 결과에 따른 작업 차단은 하지 않습니다.

- **대상:** CSS, SCSS, SASS, LESS, HTML, HTM, JSX, TSX, Vue, Svelte, Astro. 일반 JS·TS는 제외합니다.
- **제외:** 삭제 파일, 비 UI 파일, 숨김·의존성·생성 파일. 쉘 명령과 외부 편집기는 이 훅의 범위가 아닙니다.
- **권한 및 엔진:** 파일 읽기와 엔진 실행 전에 Native 권한을 확인하며 허용 규칙을 추가하거나 거부를 우회하지 않습니다. 이미 설치된 플랫폼 엔진만 사용합니다. 엔진 누락·실패·시간 초과는 검사 불가로 표시하고 다운로드하지 않습니다.
- **검사 범위:** 허용된 파일의 복사본만 격리 검사합니다. HTML은 연결 CSS를 따라가지 않는 정규식 검사입니다. 프로젝트 설정·디자인 시스템, URL·렌더·전체 프로젝트를 읽거나 검사하지 않습니다.
- **설정 동작:** `--no-config`로 실행하므로 프로젝트 무시 설정도 적용되지 않습니다. 경고는 맥락에 맞게 판단해야 합니다.
- **한도:** 파일당 최대 512 KiB, 엔진 실행 1.5초(종료 정리는 별도), 편집당 최대 8개 파일과 총 6초 검사 예산입니다. 결과는 세션·에이전트·내용·엔진이 같을 때 재사용하며 대기열을 쌓지 않습니다. 한도 초과나 동시 검사 중 생략은 결과에 표시합니다.

플러그인은 OpenCode 런타임이 의존성을 제공합니다. 플러그인 폴더에서 `npm install`하지 않습니다. 비활성화할 때는 프로젝트 또는 전역 설정의 `plugins`에 `"-ksi.impeccable-detector"`를 추가합니다. 전역 자동 재로딩을 확인하고, 다른 세션이 실행 중이면 서비스를 임의 재시작하지 않습니다.

## 자동 검사 명령

단위 검사와 Native 훅 통합 검사는 다음과 같습니다.

```sh
node --test tests/core.test.mjs tests/adapter.test.mjs
node tests/native-hook-integration.mjs
```

Native 통합 검사는 고유한 임시 HOME, 별도 포트, 로컬 모의 모델을 사용해 실제 모델 비용이 들지 않습니다. 임시 증빙은 `/tmp/opencode/ksi-native-*`에 남기며 기존 폴더를 지우거나 공유 서비스를 재시작하지 않습니다.

완료 판단 지침의 기본 회귀 검사는 다음과 같습니다.

```sh
node --test tests/completion-guidance.test.mjs
```

## 선택형 실모델 검사

아래 검사는 기본 테스트가 아니며 현재 연결된 OpenCode Go의 `deepseek-v4.1-flash#max`를 사용해 계정 사용량을 소비합니다.

```sh
node tests/completion-guidance-live.mjs --phase after --case all
```

검사는 고유한 `/tmp/opencode` 작업 공간에서 중간 완료 후 계속 실행, 외부 blocker와 독립 작업, 범위 경계를 확인하며 케이스마다 사용자 프롬프트를 한 번만 보냅니다. `--phase`는 증빙 구분용으로 적용 지침 버전을 바꾸지 않습니다. 작은 fixture 통과만으로 긴 프로젝트에서 같은 문제가 재발하지 않는다는 것을 입증하지는 않습니다.

2026-10-15 확인에서는 기존·수정 지침 모두 3/3 완주했습니다. 수정 후 검사는 시험용 권한도 좁혔으므로 기능 회귀 확인으로 해석해야 합니다. 지침 개선 효과나 긴 세션 문제 해결을 입증하는 A/B 결과는 아닙니다.
