# 시각 작업 도구

일반적인 UI 요청에서 **공식 스킬 → 실제 제품·디자인 자원 → 렌더 이미지 → 원래 문제와의 비교·교정**을 연결하는 얇은 Native V2 어댑터입니다. 더 긴 역할 프롬프트나 새 실행 엔진으로 대체하지 않습니다.

> **상태 (2026-10-29):** 배포 호스트에서 선택 발췌·검토 자료 재확인 변경의 설치 파일 일치와 당시 세션의 합성 PNG 두 장을 이용한 네 도구 연결을 확인했습니다. 이전 `visual_prepare` 호출 두 번은 요청을 읽을 수 없다는 오류로 실패했고, 새 요청 후 성공했지만 실패의 근본 원인은 미확인입니다. 실제 제품 품질 향상은 입증되지 않았습니다. [검증과 한계](validation.md)

Open Design의 스킬·자원·미리보기 조합 방식을 참고했지만 그 앱·스킬·실행기를 로컬 포크하거나 설치한 것은 아닙니다. 기존 OpenCode Native 실행과 공식 외부 설치 경로를 유지하는 범위로 구현했습니다.

## 일반 요청에서의 동작

“이 임무 화면 디자인을 개선해줘”처럼 화면과 작업 의도가 명확하면 설치된 `impeccable`을 Native prompt skill attachment로 연결합니다. 흐름·온보딩이 명시되면 `journey`, 정보·탐색 구조가 명시되면 `organize`를 보완합니다. 스킬 원문·참조 자원은 공식 설치 위치에서 Native가 해석합니다.

- 보수적인 한국어·영어 문장 감지입니다. 저장소의 후속 소스는 모달·버튼 등 명시적 컴포넌트와 일부 동작 표현을 더 인식하지만, 모호한 요청을 놓치거나 백엔드 문장을 잘못 연결할 수 있습니다. 일부 UI 제외 표현은 정상적인 읽기 전용 검토까지 놓칠 수 있습니다. 모든 표현·후속 요청을 이해하는 분류기는 아니며, 하네스·스킬·런타임 자체를 다루는 요청은 제외합니다.
- 명시적 스킬 선택과 `autoinvoke: false`는 존중합니다. 관련 스킬이 없으면 설치하거나 본문을 복제하지 않습니다. 다른 관점은 담당자가 평소처럼 선택합니다.
- 사용자 원문·모델·역할·권한을 바꾸지 않습니다. 분석만 요청한 경우 구현 허가로 해석하지 않습니다. **문장 감지가 읽기 전용 보안 격리를 제공하지는 않습니다.** 엄격한 비수정은 Native 세션 권한으로 제한해야 합니다.
- 사용자가 아래 도구 순서나 디자인 해법을 직접 지시할 필요는 없습니다. 렌더·판단·교정은 담당 에이전트가 수행합니다. **어댑터 자체는** 자동 재촉·필수 검토자 수·고정 승인 단계를 추가하지 않습니다. 선택한 공식 스킬에는 과업 범위에 따른 별도 절차가 있을 수 있으며, 사용자 지시·Native 권한·승인 범위를 우회하지 않습니다.

## 도구

| 도구 | 입력과 결과 |
| --- | --- |
| `visual_prepare` | 현재 프로젝트의 실제 구현 파일 `target`과 제품 정본·토큰·컴포넌트 등 `resources` 최대 4개를 읽어, **해당 세션의 최신 사용자 유형 메시지**·원문 발췌·해시·설치 스킬 위치를 반환합니다. 필요할 때 전체 목표 `overallGoal`과 담당 범위 `assignedScope`를 각각 선택 입력할 수 있습니다. 스크립트·앱·모델을 실행하지 않습니다. |
| `visual_capture` | `adapter: "existing"`으로 프로젝트 안의 PNG를 읽거나, `"android-emulator"`와 명시적 `emulator-NNNN`으로 이미 실행 중인 로컬 에뮬레이터를 캡처합니다. 실제 이미지와 세션·작업별 receipt를 반환합니다. |
| `visual_review` | 두 receipt와 원래 관찰한 `problem`을 받아 사용자 요청·출처·소스 차이·실제 전후 이미지를 함께 반환합니다. 자동 PASS나 디자인 인수 판정은 하지 않습니다. |
| `visual_review_single` | 이전 화면이 없거나 비교할 만한 전 화면이 없는 경우 receipt 한 개와 `problem`을 받아 실제 이미지와 맥락을 반환합니다. 이전 대비 변화나 제품 인수를 판단하지 않습니다. |

웹은 기존 Native Browser 또는 Playwright로 렌더하고, 프로젝트 안에 저장한 PNG를 가져옵니다. 별도 브라우저 엔진은 추가하지 않습니다. Android 경로는 로컬 ADB 서버 `127.0.0.1:5037`에 고정된 smart-socket 요청 두 개(`host:transport:emulator-NNNN`, `exec:screencap -p`)만 보냅니다. ADB 프로세스·daemon, 에뮬레이터·앱을 시작하거나 앱을 설치하지 않고 실 RC·원격 장치에 연결하지 않습니다.

`state`는 같은 화면·상태 이름, `provenance`는 실제 캡처 경위·빌드·입력·한계, `simulated`는 모의 입력 여부입니다. 도구에 전달한 출처는 **호출자가 선언한 정보**이며 독립 검증이 아닙니다. 그림이 같은 상태인지도 에이전트가 확인해야 합니다.

`originalRequest`는 기존 호환 필드로, 최상위 사용자의 원문을 보장하지 않습니다. 자식 세션에서는 위임문일 수 있습니다. 선택 입력한 `overallGoal`·`assignedScope`도 **호출자 선언·미검증**이며 권한이나 제품 정본이 아닙니다. 두 값이 없으면 미확인으로 표시하고, 부모 세션을 자동 탐색하거나 다른 대화를 일괄 수집하지 않습니다.

설계 전 관련 정본과 실제 화면에서 제품 목적, 사용자 상황·흐름, 보존할 유용한 요소, 정직·안전 제약과 변경 이유를 확인합니다. 큰 방향 불확실성은 관련 여정·와이어프레임 스킬로 해소하고, 중요한 화면은 원래 문제·실제 사용자 피드백·관련 맥락·이미지 경로와 receipt 해시를 허용된 fresh reviewer에게 전달해 물질적인 개선 여부를 묻습니다. **자식은 부모의 이미지나 receipt를 자동 상속하지 않습니다.** 자식이 자기 Native 권한으로 이미지를 읽거나 지원되는 첨부 수단으로 받아야 합니다. 가능하면 receipt 해시와 대조하고, 연결을 확인하지 못했다면 미확인으로 남깁니다. 수정 목록 확인과 전체 제품 판단은 분리하고 작은 차이를 큰 개선으로 포장하지 않습니다. 이는 고정 점수나 모든 작은 변경의 필수 절차가 아닙니다.

사용자가 비교를 요청한 경우 [선택형 오프라인 비교 보조](ux-evaluation.md)를 하네스 저장소에서 사용할 수 있습니다. 실제 요청·조건·피드백에서 민감정보를 제거한 기록을 **직접** 만들어 전달해야 하며, 시각 도구·이미지·사용자 피드백을 자동 수집하거나 다른 프로젝트에 설치하지 않습니다.

## 증거를 해석하는 법

- 가져온 이미지의 `registeredAt`은 **등록 시각**이지 촬영 시각이 아닙니다. 새 렌더·과거 캡처·모의 입력·실기 검증은 서로 다릅니다.
- `sourceSha256`은 등록 당시 소스 파일 해시입니다. 그 이미지가 해당 소스로 빌드됐다는 증거가 아닙니다. `afterSourceStillCurrent`도 소스 파일 일치만 나타냅니다.
- 단일 검토의 `sourceStillCurrent`도 같은 단일 대상 파일 일치만 나타냅니다. 두 검토 도구는 이미지와 패킷을 **반환**할 뿐 스스로 화면을 관찰하거나 품질을 판정하지 않습니다.
- 해상도·화면 이름·adapter·입력 분류가 다른 두 receipt, 바뀐 PNG, 다른 세션·준비 작업의 receipt는 비교를 거부합니다. 같은 이미지는 `sameImage: true`로 남깁니다.
- 새 사용자 요청이나 `visual_prepare` 재호출은 이전 준비 작업을 무효화합니다. 같은 요청에서 여러 상태를 비교하려면 한 준비 작업 안에서 상태별 receipt 쌍을 만듭니다.
- receipt는 메모리에만 있으며 플러그인 재로드·서비스 재시작 후 사용할 수 없습니다. 준비 128세션·receipt 512개 한도는 플러그인 인스턴스 기준입니다.
- 최종 결과는 항상 `acceptance: "not-evaluated"`입니다. 전체 제품·시각 판단, 특정 수정 목록 확인, 미검증 실기 동작을 분리합니다. 독립 검토가 유용하면 허용된 역할에 실제 이미지를 함께 전달하고, 중요한 문제를 고친 뒤 다시 렌더합니다.
- 브라우저의 서버 로컬 캡처가 프로젝트 밖에 있으면 현재 `existing` 경로로 바로 가져올 수 없습니다. 별도로 Native 읽기와 해당 제품 정책이 허용한 경우에는 기존 읽기 수단으로 직접 검토할 수 있지만 receipt와 자동 연결되지는 않습니다. 분석 전용 작업에서 이 제한을 우회하거나 프로젝트에 쓰기 권한이 있다고 가정하지 않습니다.

외부 단일 파일 가져오기는 현재 **미지원**입니다. Native의 일반 읽기 허용이나 호출자가 선언한 경로·출처는 이 어댑터의 외부 가져오기 권한이 아닙니다. 디렉터리 전체 승인이나 임의 `/tmp` 허용으로 대체하지 않습니다.

**신뢰 경계:** 이것은 어댑터의 접근 범위에 관한 제한이지 호스트 전체 격리가 아닙니다. 같은 OS 사용자로 실행되는 다른 프로세스, 악성 서버 플러그인 및 Native API에 접근 가능한 폭넓게 허용된 셸은 이 경계 밖입니다. 이미지가 도구 결과로 반환되면 대화와 모델 처리 경로로 전달될 수 있고, 나중에 권한을 철회해도 이미 전달된 사본은 회수할 수 없습니다. 실제 운영 데이터나 민감정보는 선택하지 않습니다.

### 스킬의 적용 범위

공식 스킬의 세부 절차는 해당 작업에 적용될 때 따릅니다. 예를 들어 Impeccable의 신규 화면·시각 세계 작업과 일부 comp-led 작업에는 질문이나 선택 절차가 있지만, 작은 기존 화면 수정에 그 절차를 일괄 적용하지 않습니다. 합성 자료가 실제로 오인될 수 있다면 적절히 표시하되, 모든 화면에 무조건 배지를 추가하는 규칙으로 일반화하지 않습니다. 필수 절차가 현재 권한이나 명시적 사용자 선택과 충돌하면 권한을 우회하지 않고 한계를 보고합니다. 외부 스킬 원문을 하네스가 임의로 수정하지 않습니다.

선택된 스킬 경로는 `visual_prepare`가 보고한 Native 선택 결과를 따릅니다. 제공자별 공식 설치 사본은 경로·본문이 다를 수 있으므로 다른 사본을 활성본이라고 단정하지 않습니다. Impeccable 안내에 따르면 해당 런처는 첫 실행에 바이너리를 내려받을 수 있습니다. **어댑터는 런처를 실행하지 않으며**, 실제 스킬 실행의 네트워크·설치·비용은 현재 권한과 사용자 정책에 따릅니다.

## 권한·파일·자원 제한

원문·자원·가져온 PNG는 현재 프로젝트 내부의 실제 경로만 허용하고 Native `read` 권한을 확인합니다. 알려진 자격증명·내부 경로를 제외하지만 **범용 비밀정보 탐지기는 아닙니다.** 자원 파일·PNG·도구 결과는 모델에 전달되므로 민감한 자료를 선택하지 않아야 합니다.

에뮬레이터 캡처는 해당 명령 자원의 Native `shell`, 저장은 Native `edit` 권한이 필요합니다. PNG는 소유자 전용 `/tmp/opencode/ksi-visual-*`(다른 OS에서는 임시 폴더)에 남습니다. 임시 PNG의 자동 삭제는 하지 않으며, 사용 중인 receipt가 없을 때 정확한 해당 폴더만 정리할 수 있습니다. 가져오기는 파일을 복사하거나 수정하지 않습니다.

텍스트 파일은 각 2 MiB 이하이며 기본 발췌는 앞 12,288자입니다. 긴 파일은 Native 읽기·검색으로 관련 부분을 먼저 확인한 뒤 `resourceOffsets: [{"path":"DESIGN.md","offset":15000}]`처럼 `resources`에 포함된 파일의 **0부터 시작하는 UTF-16 문자 오프셋**을 지정할 수 있습니다. 발췌에는 오프셋·전체 문자 수·잘림·전체 파일 해시가 표시됩니다. 하나의 파일에 발췌 하나만 선택할 수 있으므로 여러 부분이 필요하면 별도 읽기와 전달이 필요합니다.

두 검토 도구는 각 선택 자원의 Native `read` 권한을 다시 확인해 검토 시점에 읽은 발췌만 반환합니다. `preparedSha256`과 현재 `sha256`이 다르면 `changedSincePrepare: true`이며, 편집된 파일의 같은 오프셋이 원래 부분을 가리킨다는 보장은 없습니다. 선택 경로의 실제 대상이 바뀌었거나 오프셋이 사라지면 검토를 중단합니다. 새 준비는 이전 receipt를 무효화합니다. 권한 철회 전 이미 대화에 전달된 내용은 소급 삭제되지 않으며, 검토 직후 변경이나 정본 여부는 자동 판정하지 않습니다.

PNG는 8 MiB·8192px 축·2천만 픽셀 이내의 구조를 확인합니다. 완전한 PNG 디코딩·빌드 검증·화면 의미 검증은 아닙니다. ADB 통신은 총 15초 제한과 취소를 지원합니다. Linux에서는 열린 파일 descriptor의 실제 경로도 확인해 승인 대기 중 경로 교체를 거부합니다. 다른 OS의 동일한 경합 방어는 미검증입니다.

## 설치·확인·해제

```sh
node scripts/install-visual-workflow.mjs
node scripts/install-visual-workflow.mjs --verify
node tests/visual-workflow-native.mjs
```

설치기는 `$XDG_CONFIG_HOME/opencode/plugins/ksi-visual-workflow/` 또는 `~/.config/opencode/plugins/ksi-visual-workflow/`에 두 실행 파일과 해시 manifest만 둡니다. 빈 `XDG_CONFIG_HOME`은 미설정으로 취급하고, 상대 경로는 잘못된 위치에 쓰지 않도록 거부합니다. 외부 스킬·모델·MCP·hook을 설치하거나 바꾸지 않습니다.

기존 managed 버전은 백업 후 파일별 교체합니다. 수정·미관리 파일, manifest에 기록된 파일의 누락, 예상 밖 디렉터리 항목이나 중단된 설치의 임시 파일, 상위 경로를 포함한 심볼릭 링크는 설치와 `--verify` 모두 안전 중단합니다. 다른 진입점이 있으면 Native가 다른 파일을 로드할 수 있으므로 보존하고 먼저 확인합니다. 경로·해시 검사는 검사 후 교체 사이에 경합 가능성이 있으며, 파일별 교체이지 전체 디렉터리의 트랜잭션은 아닙니다. 중단되면 재실행으로 덮어쓰지 말고 백업·현재 해시부터 확인합니다.

설치기는 다른 플러그인의 동일한 `visual_*` 도구 ID 충돌은 검사하지 않습니다. 같은 이름의 나중 등록이 앞선 정의를 덮을 수 있으므로 적용 전 목록과 소유자를 확인하세요.

OpenCode 파일 감시로 반영되며 공유 서비스 재시작은 필요 없습니다. 직후 catalog가 비어 있으면 로딩 중일 수 있습니다. `--verify`는 파일 해시 검사이고 활성화는 별도 Native plugin catalog에서 `ksi.visual-workflow`의 `active` 상태로 확인합니다.

해제할 때는 정확히 해당 플러그인 디렉터리를 발견 경로 **밖의 비공개 백업 폴더로 이동**합니다. 기존에 다른 내용이 섞였으면 먼저 확인하고, 다른 플러그인·스킬 디렉터리를 통째로 지우지 않습니다. 외부 스킬은 유지됩니다. 재로드로 receipt가 무효화되는 점에 주의하세요.
