## Goals / Non-Goals

**Goals:**

- Rebind `engineer-workflow` to five operating profiles with Native autonomy, concrete file surfaces and testable scenarios — no generic framework.
- Remove with backup (user-authorized): delete the 4 superseded specialist operating files outright — global-JSONC `disabled` was proven ineffective at suppressing retained Markdown profiles in isolation — keeping their last-approved contents only in private backups; unremoved files block deployment rather than passing silently.
- Migrate tests/scripts/docs without weakening honesty: keep completed/failed/incomplete/identity/coverage reporting and historical trace parsing; drop only normative optional-skill gap inference.

**Non-Goals:**

- No shared-service restart, forced existing-session changes, commits/pushes or archives as part of this apply. The proposal's earlier planning-only boundary is historical, not a freeze on approved implementation.
- No new router/plugin/reviewer profile/report/scorecard/mandatory loop; no per-purpose timeout, provider-fallback, or custom skill machinery.
- No deletion/archive beyond the four expressly retired specialist operating files; Architect retention and other historical files remain protected. No auto-edit of other projects' duplicated role instructions (reported as conflicts only).
- No mandatory benchmark/task quota or quality certification to finish this migration; optional real-product observation lives as prose below, never as a task gating this change.

## Decisions

1. **One modified capability (`engineer-workflow`), `skip_specs` NOT set** — the delta explicitly MODIFIES Unit routing, Work-unit ownership, Task-fit/evidence, Loop boundaries, External skills/detector, Artifact ownership, Prompt role-boundary semantics, and ADDS five-profile/Native-autonomy, result-verification-with-OPTIONAL-independent-checks/enforced-boundary, and retired-operating-profile-removal/backup requirements. Unchanged Native context/MCP/architect/staged-skills/canonical-workflow/model-caveat requirements are preserved via merge, not copied.
2. **Lead = short responsibility prompt, not a method merge** — alternative (concatenating Engineer+Design+Research bodies) rejected: it would re-impose forced skill stages, CSS authorship and visual prescriptions the user explicitly removed. Lead owns the full assigned task from research/UX/design through implementation/test/recovery/completion; it may implement directly and may use zero/one/several General workers sequentially/parallel as useful (not management-only) with objective+scope delegation and same-task session reuse, and remains accountable for the actual result; General owns its assigned task execution; method detail lives in Native lenses on demand. Build owns product goal/planning/work decomposition/parallelism/dependencies/integration/final acceptance and MAY implement directly or use General directly — NOT ONLY tiny/single-file/UI-free work — with no mandatory Lead routing by complexity/file-count/domain.
3. **Native breadth restored by deletion, not by new allows** — General: remove KSI skill-whitelist narrows; General retains Native broad research/design/UX/multi-file implementation/test/repair skills/tools inside objective+scope, owns task execution, self-verifies and returns results normally, reporting material uncertainty upward; it gains no child/question capabilities (Native baseline) and takes on no mandated independent review — explicit task-local review/analysis restrictions and higher-priority security policies remain valid; General may use UX/research/security skills with no configuration whitelist and no permanent KSI tool/skill whitelist is added. Explore: Native code + web search with read-only analysis, analyzing and reporting its searched scope; neither acceptance owner nor implementation worker. Plan: mode `all` as a deliberate consultation exception (user-selectable OR optional Build/Lead advisory call) with Native prompt/edit limits intact — no custom system/allowlist, no implementation, no requirement/product approval, never an approver/mandater/vetoer of independent verification nor a review dispatcher; it may delegate ANALYSIS ONLY within its approval scope and depth (General for analysis only, under explicit boundaries — never an implementation bypass); Build/Lead child allowlists now include plan+general+explore (Build also lead); no forced Plan stage and no Plan approval gate. `system` untouched; `subagent_depth: 3` kept as ceiling that the optional Build→Lead→Plan→General advisory chain MAY reach when consultation is chosen (never required); a Plan at the cap analyzes directly and returns the gap.
4. **Result verification with OPTIONAL independent checks; enforcement via session restrictions or isolated env** — alternative (edit-deny line as proof) rejected: it does not stop shell/browser/network effects. Actual verification IS required (applicable code/tests/regression/runtime/render/interactions/persistence/failure plus original requirements) and default work ends when requirements are verified, not when a critic is satisfied; independent LLM critique is never a default stage, pass-gate, or mandatory per-task question (no quota, no mandatory critic→fix→critic pipeline — a chosen check that finds a real unresolved risk MAY still get a proportionate chosen recheck — no justification report when omitted). Build chooses optional independent checks for product/integration/important risk; Lead autonomously chooses for its OWN assigned scope with no Build approval needed within existing authorized resources/contracts/costs; General self-verifies and reports material uncertainty upward (it cannot spawn a reviewer); Plan only analyzes plans/design alternatives. Concurrency/data-loss/security/migration/repeated-failure/UX-flow risks are NOT automated triggers forcing AI review — reproducible tests/static analysis come first, and a fresh uninvolved General is chosen only when a useful specific verification question exists (original task + actual code/renders/evidence provided; `No issue found` is valid; no compelled findings or design-taste churn). Required security/safety checks and human signoffs where an existing contract requires them remain; no mandatory AI critic is added. A chosen independent check is normally non-mutating (never a default stage); provable non-mutation requires explicit Native denies or sandbox + failing-closed test with byte checks, and tests for the OPTIONAL restricted-verification capability prove mechanics only (no production gate/profile/plugin).
5. **Authorized removal with private backup, then actual absence/call-failure proof** — the 4 superseded specialist operating files are deleted outright with user approval (last-approved contents survive only in private backups); deleting the files removes their routing — not the underlying research/UX/verification abilities, which continue via Lead/General/Explore Native breadth. Legacy `docs/archive/agents/architect.md` retention is preserved unchanged. No `disabled` tombstone, hidden entry, or custom loader stands in for removal (global-JSONC `disabled` was proven ineffective against retained Markdown profiles in isolation). The only-five-profiles catalog plus blocked retired calls must still be proved with actual absence and actual fresh-call failure; if not proved, deployment stays blocked/partial and verification is not marked done — no custom fallback framework.
6. **Session-audit: drop normative skill inference, keep honesty** — remove `design-edited-without-ux-or-craft-skill` / visual-capture-mandate / `critic-reviewed-without-skill-lens` as failure gaps (they mandate optional lenses); preserve completed/failed/incomplete separation, file/identity/coverage honesty, historical trace parsing and its tests. Alternative (keeping them as warnings) rejected: warnings still gate behavior by convention.
7. **Test migration without pinned pass counts** — update `TRACKED_AGENTS` to 5, `capabilities.test` expectations, `agent-routing-native` role/mode/edge checks (Plan mode `all` as a deliberate consultation exception: user-selectable OR optional Build/Lead advisory call; Build child edges Lead/General/Explore+Plan, Lead child edges Plan/General/Explore; no forced Plan stage and no Plan approval gate), `delegation-native-integration` graphs (Build→Lead→General/Explore, Build→General direct, optional Build→Lead→Plan→General advisory chain that MAY reach the retained ceiling of 3 when consultation is chosen, and optional fresh-General checks only when chosen — plus a positive NO-independent-review completion path; self-verification/evidence/failure coverage and shared-file ownership), and `prompt-boundaries` sources (Lead + common AGENTS + Native edges; retire 3-specialist reads). Tests assert the merged new contract plus preserved untouched requirements — never equality with this partial delta or the old change. Other existing suites change only with proven semantic migration. No exact check-count target is set for rewritten suites; no test certifies model judgment quality.
8. **Merge (not equal) at later apply via the official delta merge/sync mechanism** — the main spec keeps its six unchanged requirements (Native context, MCP, architect-retention, staged-skills, model-caveat, canonical workflow) byte-preserved while the seven modified requirements take the delta's content and the three added requirements land; historical evidence is never rewritten. The old open change `engineer-unit-openspec-skills` is NOT rewritten and its empirical tasks 5.1/5.2/5.4/5.5 are NOT marked done; its assertions are read against its own frozen baseline, and validation may check both artifacts without claiming old roles are current. The apply records the merge output and both validation results.
9. **Deployment: backup-first, session-safe, staged retirement** — later apply backs up live config/roles, checks for active legacy (Engineer/Design/Research/Critic) sessions and never force-ends/switches them; retirement stages only after idle; no shared-service restart. Compaction/`tool_output` omission, `mcp.servers` URLs/env-header/oauth split + auth state, provider body, other preferences/models, skill bytes/locks, and archived `architect.md` bytes are preserved verbatim.

## Risks / Trade-offs

- [Risk] Loader ordering for `disabled` suppression PROVEN ineffective (isolated steady-state probes: retained Markdown profiles reappear despite exact global-JSONC `{disabled:true}`; project-point `disabled` works, file-point works on copies) → Resolution: user authorized outright removal of the 4 operating files with private backup instead of tombstones; the actual-absence/call-failure proof below replaces the suppression proof.
- [Risk] Two open changes touching one capability collide at apply → Mitigation: decision 8 merge sequencing + `openspec validate <change>` and `--all` both run; old change never force-archived to satisfy validation.
- [Risk] Broadened General/Explore permissions widen blast radius → Mitigation: assigned-task ownership with self-verification and normal completion return, reporting material uncertainty upward; enforced session denies for strict optional reviews, least-privilege task-local copies; role allows are not OS sandboxes (stated limit).
- [Risk] Removing skill-stage mandates is read as removing skill value → Mitigation: lenses stay available on demand with per-run evidence; no quota either direction.
- Trade-off: five profiles are coarser than eight specialties, but match the user's task-completion intent; specialty depth now lives in Lead judgment + Native lenses, not in routing edges.
- Optional real-product observation (prose only, gates nothing): genuine future product work retaining UI-render and real-outcome proof would evidence behavior, but config checks alone never establish quality; no observation is authorized here.
