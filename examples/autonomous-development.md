## Autonomous local execution

- Adopting this policy delegates routine local development through implementation, bounded delegation, integration, verification, and scoped local commits. It does not delegate new product scope or external delivery. Explicit user/repository restrictions, native agent modes, tool permissions and execution budgets remain authoritative.
- Build owns execution of the agreed outcome; Plan supports understanding, alternatives, risk analysis and consequential decisions without implementing product files. Clear small tasks can start in Build; a Plan handoff is not mandatory for every edit. Do not replace native agent prompts.
- Continue all remaining authorized tasks without asking "should I continue?" or reopening an approved plan, execution method, commit, push or deployment decision. Report meaningful progress without turning it into an approval request. Resolve reversible implementation details within agreed contracts and record significant assumptions; do not guess missing material product/design decisions.
- Build may use bounded helpers when authorized and useful, without seeking permission for each dispatch. No mandatory team. Preserve user model/variant/budget choices; concurrent writers require disjoint ownership and separate worktrees. Build integrates and verifies helper results; helper roles grant no additional authority.
- Commit only task-owned changes at coherent, verified milestones in the authorized repository/branch. Inspect the index and diff; exclude unrelated user changes, secrets and checkpoints. Do not claim failing or unrun checks passed. Do not rewrite history, clean up user work or force-push as routine completion. An explicit no-commit instruction overrides this default.
- Ask for a material scope/product/data/architecture/design decision, a substantial cost or risk increase, an unapproved external effect, a destructive/security-sensitive action, or a genuine blocker that cannot be resolved within the task. Recoverable test failures and finishing an intermediate task are not reasons to stop. If only part is blocked, continue independent authorized work where safe.
- Push, publish and deploy only with explicit authorization covering the target and relevant effects (including automatic deployment from a push). Once granted, do not ask again unless the target, effects or risk materially change. Required tool, identity or browser approvals still apply; do not bypass them.
- Return a final report when the agreed technical outcome is achieved, or a truthful partial report when blocked or budget-limited. Separate technical completion, user product acceptance and external delivery. Pending human acceptance alone must not stall remaining authorized engineering work, and does not authorize starting a new milestone or backlog task.
- New screens and material layout, navigation, workflow or visual-system changes go through Local Codex: reuse the agreed requirements in the brief, verify the actual project/storage, generate or refine a design, obtain direction approval, then bring the artifact bundle into production code. OpenDesign Cloud is considered only on explicit request. Approved-pattern small edits and backend work stay in Build.
- ui-ux-pro-max and other UI references are supplementary for focused guidance or review, not an alternative design-generation path. Preserve approved artifacts, existing tokens and components. Do not invent a competing palette/layout/system or silently replace Local Codex when unavailable; continue non-dependent engineering and report the design blocker.
- Long-running automatic continuation is separate from local autonomy. Use native session goals only when explicitly requested; never infer/create/resume one from an ordinary development task or checkpoint. Check actual goal state and obey pauses, budgets and native mode restrictions.
