# Shared project guidance (optional template)

Use this file as a short repository-level `AGENTS.md` only when these paths and conventions fit the project. OpenCode and Codex can read the same project guidance; their agent configurations remain independent.

- Treat the current code, tests, and Git state as evidence. A checkpoint is a resume pointer, not proof that work is complete.
- If present, `docs/superpowers/product-state.md` records the current product milestone and user-visible acceptance. Use `docs/superpowers/plans/` for the relevant task decision and verification record, and `.opencode/working-state.md` for a compact worktree handoff.
- Use installed skills, including Superpowers, when they help the task. Do not copy or modify upstream skills to restate local policy. Skills and roles do not grant authority beyond the user's request.
- Scale planning, delegation, review, and visual evidence to the work. Preserve unrelated changes, report checks actually run, and distinguish local evidence from user acceptance or deployment readiness.
- Parallelize only separable work. Read-only discovery or review can overlap; concurrent writers need disjoint paths, stable interfaces, and separate worktrees. The coordinating Primary integrates and verifies the result.
- Adopt the [autonomous local execution policy](autonomous-development.md) by merging its section into this guidance (do not assume a linked file is automatically loaded). That policy delegates approved implementation, bounded helpers, integration, verification and task-owned local commits without routine progress/commit confirmation. Explicit user/repository restrictions still win.
- Pushes, releases and deployments need explicit authorization for their targets and effects, including push-triggered deployment. Reuse valid prior authorization instead of asking again. Material product/design decisions, destructive/security-sensitive actions and genuine blockers still return to the user.
- Local Codex owns new/material visual and interaction design; reuse approved artifacts for production integration. ui-ux-pro-max is supplementary guidance/review, not a competing design system or a silent fallback.
- OpenCode researches Mobbin conditionally before new/material design and passes inspected patterns/links/accessible images in the same agreed brief. Record approval against a required-file content snapshot; design preview and actual product-server verification are separate. See the [handoff procedure](../docs/integrations/opendesign.md#reference-research-and-brief-transfer); no automatic reverse engineering-session calls or runtime enforcement is implied.
