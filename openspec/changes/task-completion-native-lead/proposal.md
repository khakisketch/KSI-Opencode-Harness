# Proposal

## Why

The user adopts task completion — not role-method prescriptions — as the operating model: five operating roles (Build/Lead/General/Plan/Explore) with Native behavior restored. The current 8-role contract (Build/Plan/General/Explore + custom Engineer/Design/Research/Critic) plus KSI forced skill-load stages, CSS authorship, blanket visual preferences and single-file-only limits conflicts with that intent and with OpenCode V2 Native defaults for General/Explore/Plan.

## What Changes

- Collapse the four custom specialist roles (Engineer/Design/Research/Critic) out of default operations; introduce **Lead** as the assigned whole-workflow owner under Build. Lead owns the full assigned task from research/UX/design through implementation/test/recovery/completion (not management-only) and remains accountable for the actual result; General owns its assigned task execution. Lead carries a short responsibility prompt, not merged Engineer+Design+Research methods.
- Restore Native autonomy. **Build** owns product goal/planning/work decomposition/parallelism/dependencies/integration/final acceptance; it MAY implement directly or use General directly — NOT ONLY tiny/single-file/UI-free work — with no mandatory Lead routing by complexity/file-count/domain. **Lead** owns the full assigned task from research/UX/design through implementation/test/recovery/completion; it may implement directly and may use zero/one/several General workers sequentially/parallel as useful (not management-only) and remains accountable for the actual result. **General** retains Native broad research/design/UX/multi-file implementation/test/repair skills/tools inside objective+scope, owns task execution, self-verifies and returns results normally, reporting material uncertainty upward; it gains no child/question capabilities (Native baseline) and takes on no mandated independent review; explicit task/session/managed-security restrictions remain valid with no permanent KSI tool/skill whitelist. **Explore** regains Native code + web search with read-only analysis — analyzing and reporting its searched scope — not an OS sandbox, acceptance owner, or implementation worker.
- **Plan** runs mode `all` (deliberate consultation exception, not claimed as Native default): user-selectable OR optional Build/Lead advisory call with Native prompt/edit limits intact; it implements nothing and approves no requirements/products, never approves/mandates/vetoes independent verification nor acts as review dispatcher; it may delegate ANALYSIS ONLY within approval scope and depth (never an implementation bypass). Build/Lead child allowlists now include plan+general+explore (Build also lead); no forced Plan stage and no Plan approval gate. Small fixes — technical or UI — may go Build-direct/General with no obligatory Lead stage; if a unit is assigned to Lead, Lead owns the whole workflow from research/UX/design through implementation/test/recovery/completion.
- Rewrite the common AGENTS contract around five principles (goal/evidence/autonomy/responsibility/boundaries); remove forced skill stages, mandatory lenses/sequences, CSS-authorship mandates, blanket visual prescriptions and single-file-only limits. Tools and installed external skills are available on demand; each loaded skill's own limits are honored. Preserve actual runtime/render/persistence/failure evidence where applicable; no quality claims from role counts or model variants.
- Result verification with OPTIONAL independent checks (never a default stage): actual verification IS required — applicable code/tests/regression/runtime/render/interactions/persistence/failure plus original requirements — and default work ends when requirements are verified, not when a critic is satisfied. Independent LLM critique is NOT a default stage, pass-gate, or mandatory per-task question; no quota, no mandatory critic→fix→critic pipeline (a chosen check that finds a real unresolved risk MAY still get a proportionate chosen recheck), no justification report when omitted. Build chooses optional independent checks for product/integration/important risk; Lead autonomously chooses for its OWN assigned scope with no Build approval needed within existing authorized resources/contracts/costs; General self-verifies and reports material uncertainty upward (it cannot spawn a reviewer); Plan only analyzes plans/design alternatives. Concurrency/data-loss/security/migration/repeated-failure/UX-flow risks are NOT automated triggers forcing AI review — reproducible tests/static analysis come first, and a fresh uninvolved General is chosen only when a useful specific verification question exists (original task + actual code/renders/evidence provided; `No issue found` is valid; no compelled findings or design-taste churn). Required security/safety checks and human signoffs where an existing contract requires them remain; no mandatory AI critic is added. Review is normally non-mutating; provable non-mutation uses explicit Native session restrictions or an isolated environment — edit-deny alone does not stop shell/browser/network effects. Tests for the OPTIONAL restricted-verification capability prove mechanics only and add no production gate/profile/plugin. No new router/plugin/reviewer profile/report/scorecard/mandatory loop.
- Remove the four superseded specialist operating files outright (user-authorized; no longer used): their last-approved contents survive only in private backups (source working-before + installed-before sets), never auto-restored into operation. Removing the files removes their routing — not the underlying research/UX/verification abilities, which continue via Lead/General/Explore Native breadth. Global-JSONC `disabled` was proven ineffective at suppressing retained Markdown profiles in isolation, so no tombstone/hide stands in for removal. Deployment still requires the actual only-five-profiles catalog plus blocked retired calls; the exact gap is reported, never asserted away (hidden ≠ security; no custom fallback). Legacy `docs/archive/agents/architect.md` retention is preserved unchanged.
- Retained model preferences: retain General `#high` / Explore `#medium` / Plan `#xhigh`; Lead inherits current Engineer `#xhigh`; Build model unpinned. Explicitly: Native **behavior** is restored, not every model-preference default claimed (model IDs stay in proposal prose only, never in binding specs). Keep `subagent_depth: 3` as ceiling; with Plan `all`, the optional Build→Lead→Plan→General advisory chain MAY reach depth 3 when consultation is chosen — never required and never a mandated fill; a Plan at the cap analyzes directly and returns the gap (no bypass); no production self/ancestor loops. Preserve Native compaction/`tool_output` omission, `mcp.servers` URLs/env-header/oauth split and auth state, provider body, other preferences/models, external-skill bytes/locks, and `docs/archive/agents/architect.md` bytes. Rollback is backups, never an auto-fallback framework.

## Capabilities

### New Capabilities

(none — this change rebinds the existing workflow capability)

### Modified Capabilities

- `engineer-workflow`: replace conflicting Unit routing, Work-unit ownership, Loop boundaries, External skills/detector, artifact ownership and Prompt role-boundary semantics for the five-role Native model; add five-profile/Native-autonomy, result-verification-with-OPTIONAL-independent-checks, and retired-operating-profile-removal/backup requirements. Unchanged context/MCP/architect-retention/staged-skills/model-caveat/canonical-workflow requirements are preserved via merge, not copied here.

## Impact

- Proposal-time scope was four planning artifacts under `openspec/changes/task-completion-native-lead/`; implementation followed separate user approval. `.openspec.yaml` remains intact and the old change `engineer-unit-openspec-skills` stays frozen. Apply status and evidence are recorded in `tasks.md` and `docs/engineer-routing-validation.md`, not inferred from planning completion.
- Approved apply surface: `global/opencode.jsonc` (agents block), `global/AGENTS.md`, `global/agents/lead.md` (new) + removal of the four superseded specialist files (private backups kept), `README.md` / `docs/installation.md` role tables, `scripts/capabilities.mjs` + `scripts/session-audit.mjs`, affected tests (`capabilities`, `prompt-boundaries`, `agent-routing-native`, `delegation-native-integration`), and the official main-spec merge; other existing suites only if semantic migration is proven. No exact pass-count target is pinned for changed suites.
- Deployment is backup-first with an active-legacy-session check, no force-ending/switching and no shared-service restart. No mandatory benchmark/task quota or quality certification gates this migration. Other projects' duplicated role instructions are reported as conflicts, never auto-edited. Local deployment does not imply a commit, push or archive.
