## 빠른 시작

기본 메인은 **Build**입니다. 역할 전환 명령이나 고정된 단계 없이 목표와 제약만 전달하면 됩니다.

- **기능·제품 개발:** “현장 정사영상 비교 흐름을 구현하고 실제 화면과 테스트까지 검증해줘.”
- **중요한 제품·다화면 UX:** “현장 화면의 정보 구조와 시각적 우선순위를 다시 설계하고, 데스크톱·모바일 실제 렌더로 확인해줘.”
- **분석·자문만:** “현재 화면과 제품 정본을 대조해 UX 구조의 문제와 설계 대안을 분석해줘. 구현은 하지 마.”
- **장기 개발:** “승인된 범위의 다음 기능을 완성하고, 공유 계약과 실제 결과까지 확인해줘.”

사용자는 아키텍처·역할·테스트·디자인 규칙을 일일이 지정하지 않아도 됩니다. Build가 관련 정본과 실제 코드를 먼저 확인하고, 필요한 역할·모델·도구를 스스로 고릅니다.

**질문은 권한 경계에서만 합니다.** 목표 충돌, 계약·비용·보안·데이터 정책 변경, 되돌리기 어려운 작업, 접근 권한 부재, 사용자 가치가 크게 갈리는 핵심 선택에만 질문하고, 나머지는 안전한 기본값으로 진행합니다. 시각적 선택은 추상적인 설명보다 실제 화면·와이어프레임·연결 흐름 같은 구체물로 보여줍니다.

## 운영 원칙

- **목표와 맥락:** 승인된 사용자 목표를 실제 동작으로 완성합니다. 제품 목적·사용자 상황·프로젝트 정본·현재 코드·런타임 근거를 함께 보고, 확정 계약과 가설을 구분합니다.
- **소유권:** Build는 승인된 전체 목표·작업 배분·통합·최종 제품 품질을 소유합니다. Lead는 배정된 결과를 끝까지 완결하고, General은 배정 과업을 실행·검증하며, Plan은 분석·자문만 하고, Explore는 읽기 전용 탐색을 합니다. **자식의 완료는 부모 목표의 완료가 아닙니다.**
- **자율성:** 직접 개발할지, Lead·General·Explore·Plan을 쓸지, 어떤 모델·도구·스킬을 쓸지는 과업에 맞게 선택합니다. 고정 호출 순서·필수 비평·반복 횟수는 없습니다.
- **연속성:** 승인된 목표와 구현 현실, 현행 정본과 결정 이력, 제품 상태와 세션 체크포인트를 구분합니다. 변경된 지속 사실은 기존 소유 문서와 상태 원장에 반영하고, 새 목표를 임의로 만들지 않습니다.
- **경계:** 다른 사람의 변경·승인된 계약·권한·데이터 정책·배포 경로를 보존합니다. 공유 서비스·운영 환경·자격증명·기기 상태는 명시적 승인 없이 바꾸지 않습니다.

## 역할과 위임 구조

5개 운영 역할(**Build · Lead · Plan · General · Explore**)로 구성됩니다. 최대 위임 깊이는 **3**(root 0 → 1 → 2 → 3)이며, 평소에는 1~2단계를 쓰고 유용한 필요가 있을 때만 3을 씁니다. 이전 전문 4개 역할(`engineer`·`design`·`research`·`critic`)은 사용자 승인으로 저장소와 전역에서 제거했습니다.

| 역할 | 책임 | 모드 | 기본 모델 | 하위 호출 |
| --- | --- | --- | --- | --- |
| **Build** | 승인된 전체 목표, 작업 배분, 통합, 실제 결과 판정, 최종 품질 | `primary` | 세션 선택 (전역 미고정) | `plan`, `lead`, `general`, `explore` |
| **Lead** | 배정된 기능·업무 흐름을 조사·설계·구현·검증·복구까지 완결 | `subagent` | `opencode-go/muse-spark-1.3-contributor#xhigh` | `plan`, `general`, `explore` |
| **Plan** | 복잡한 문제, 제품·UX·기술 대안, 원인 분석과 근거 기반 자문 | `all` | `openai/gpt-6.1-sol#high` | Native 분석 범위 |
| **General** | 배정된 과업을 범위 안에서 실행·검증하고 결과·위험을 반환 | `subagent` | `opencode-go/muse-spark-1.3-contributor#high` | 없음 (말단) |
| **Explore** | 코드·외부 자료 탐색과 읽기 전용 분석 | `subagent` | `opencode-go/muse-spark-1.3-contributor#medium` | 없음 (말단) |

### 좋은 위임 경계

- **Lead:** 사용자가 자료를 선택하고, 두 시점을 비교하고, 결과를 이해하는 **전체 흐름**처럼 끝까지 완성할 기능·업무 흐름.
- **General:** 범위가 정해진 실행, 조사, 구현, 테스트, 수리.
- **Plan:** 방향·대안·원인 판단이 불명확하거나, 여러 선택지를 독립적으로 분석할 때.
- **Explore:** 코드·자료·외부 문서에서 특정 정보를 찾을 때.
- **Build 직접:** 작은 수정이나 핵심 구현. 모든 일을 위임할 필요는 없습니다.

파일·CSS·버튼처럼 기술 조각만 나누면 각 조각이 끝나도 전체 화면이 좋아진다는 보장이 없습니다. **통합했을 때 사용자에게 의미 있는 단위**로 맡기고, 공유 API·상태·파일·브라우저 소유권은 Build가 먼저 조율합니다.

### 세션 수명주기

- **새 과업·독립 분석:** 새 자식 세션(`sessionID` 생략). 새 맥락은 비평뿐 아니라 문제 해석·조사·설계·구현에도 활용합니다.
- **같은 과업의 후속 분석·수정·재검증:** 기존 담당 세션(`sessionID`)을 재개합니다. ‘1 세션 = 1 슬라이스’ 같은 고정 할당량은 없습니다.
- **핸드오프:** 새 자식에게 목표·확정 계약·범위·보호 경계·실행 환경·증거 경로·완료 조건을 필요한 만큼 전달합니다. 고정된 5칸 보고 양식은 아닙니다.

### 독립 확인

독립 확인은 **기본 단계도 합격 게이트도 아닙니다.** 유용한 특정 위험이 있을 때만 선택합니다.

- UI라면 실제 렌더 화면을 주고 **제품·시각 질문**에 답하게 합니다. 코드·계약만 보는 검토는 제품 수용을 대신하지 못합니다.
- 보안·계약·데이터 위험이라면 해당 위험에 맞는 증거와 질문을 줍니다.
- `No issue found`도 유효한 결과입니다. 비평을 강제하거나 점수·보고서를 만들지 않습니다.
- 발견된 문제는 같은 담당 세션을 재개해 교정·재검증하는 것을 기본으로 합니다.

## 제품 수용

**작동 검증과 제품 수용은 다릅니다.** 테스트 통과, 스크린샷 존재, 계약 일치는 증거이지 “사용자에게 좋은 제품”의 증명이 아닙니다.

Build는 완료를 선언하기 전에 원래 목표와 실제 결과를 대조합니다. UI가 있다면 아래 기준을 **자기 판단**으로 확인합니다. 형식 체크리스트가 아니라 판단의 예입니다.

- **첫 화면:** 사용자가 처음 보는 화면에서 제품의 목적과 다음 행동이 명확한가?
- **핵심 과업:** 사용자가 원래 하려던 일을 자연스럽게 끝낼 수 있는가?
- **시각적 위계:** 정보 구조와 화면의 중심이 사용자의 업무에 맞는가? 공간정보 제품이라면 공간정보가 실제로 주인공인가?
- **상태 조합:** 빈 상태·로딩·오류·연결 단절에서도 주요 행동이 보이고 눌릴 수 있는가? 패널·오버레이가 오류 복구나 다음 행동을 가리지 않는가?
- **기존 기능:** 구현 과정에서 기존의 유용한 기능·데이터·권한·복구 경로를 훼손하지 않았는가?
- **반응형·접근성:** 목표 기기에서 읽고 조작할 수 있는가? 키보드 포커스·이름·대비·터치 영역이 실제로 동작하는가?

**정직한 빈 상태와 가짜 데이터는 다릅니다.** 실제 픽셀·출처·수치·고객 데이터를 발명해서는 안 되지만, 그 사실을 명시한 중립 표지·빈 상태·기본 커버는 제품의 시각적 위계를 위해 사용할 수 있습니다. “가짜 픽셀 금지”를 “정직한 표지도 금지”로 확장하지 않습니다.

문제가 남으면 **같은 담당자에게 구체적인 관찰 사실과 함께 교정**을 요청하고, 해결되지 않은 중요한 위험은 완료 보고에 명시합니다. 자식의 “완료했습니다”나 독립 검토의 “SHIP”을 그대로 최종 수용으로 삼지 않습니다.

## 프로젝트 지식과 상태

전역에는 지식의 **역할·선택·갱신 원칙**만 두고, 제품 사실과 권위는 각 프로젝트가 소유합니다.

- 프로젝트 `AGENTS.md`는 짧은 제품 소개와 **기존 정본을 가리키는 지도**입니다. 고정된 파일명·문서 수·독서 순서는 없습니다.
- 과업에 관련된 **제품 목적·범위**, **사용자 업무·화면 책임**, **시스템·데이터 소유 경계**, **검증된 현재 상태**를 찾습니다. `PRODUCT/EXPERIENCE/SYSTEM/STATE` 네 파일을 만들라는 뜻이 아닙니다.
- 제품 정본, 상태 원장, 결정·검증 이력, 세션 체크포인트를 구분합니다. 원장은 현재 구현·검증 근거/한계·남은 문제·승인된 작업 연결만 간결하게 유지합니다.
- 실행 담당자는 변경 사실과 근거를 반환하고, Build가 공유 정본과 원장을 통합합니다. 제품 사실이 바뀌지 않은 작은 수정에 원장 갱신을 붙이지 않습니다.
- 전역 설치로 다른 프로젝트의 문서를 일괄 생성·이전하거나, 전역 공용 제품 원장을 만들지 않습니다.

## 디자인·엔지니어링 실행

- **실제 제품을 수정합니다.** 별도 정적 HTML 목업만 만들고 끝내지 않고, 실제 라우트·컴포넌트·데이터 연결을 수정합니다.
- **스킬은 필요할 때만 씁니다.** 사용자 흐름·정보 구조에는 `designing-user-experience`(복수 화면이면 `journey`, `organize`, `wireframe`), 시각 조형·마감에는 `impeccable`, 실제 문구 검토에는 `ux-copy`를 선택할 수 있습니다. 강제 순서·필수 스킬은 없습니다.
- **코드를 먼저 대조합니다.** 문서보다 실제 파일과 최근 커밋이 우선입니다. 이미 구현된 기능을 재작업하지 않도록 `git status`·`log`와 현재 코드를 확인합니다.
- **로컬에서 자율 재빌드·검증합니다.** 자신이 소유한 번들·개발 서버·격리 컨테이너·승인된 로컬 빌드는 다시 빌드·기동해 실제 런타임에서 확인합니다. 공유 서비스·운영 환경·미승인 기기 상태는 임의로 재시작하지 않습니다.
- **원인 기반 디버깅:** 원인이 불분명하거나 반복되는 버그에는 `diagnosing-bugs` 렌즈(재현 신호 → 가설·이분 탐색 → 최소 수정 → 회귀 테스트 → 런타임 재검증)를 선택적으로 씁니다. 결과물의 실제 검증은 필수입니다.
- **정직한 상태:** 요청 접수·모의 렌더·합성 데이터를 실제 장치·운영 결과로 표현하지 않습니다. 출처·정합·검증 한계는 판단에 영향을 주는 만큼 보이게 하고, 보충 근거는 상세로 접습니다.

## 모델 운영

모델과 역할은 별개의 선택입니다. Build의 모델은 세션에서 정하며 전역에 고정하지 않습니다.

| 상황 | 권장 운영 |
| --- | --- |
| 중요한 제품·다화면 UX, 최종 디자인 판단이 어려움 | **Sol High Build**로 세션 운영 |
| 방향이 확정된 장기 개발·반복 구현 | **DeepSeek Flash Max Build** + 필요할 때 Sol Plan |
| 복잡한 문제·대안·원인 분석이 필요 | **Sol High Plan**에 선택적 자문 |
| 배정된 기능 완결 | **Lead** (Muse Contributor XHigh) |
| 범위가 정해진 실행·조사 | **General** (Muse Contributor High) |
| 코드·자료 탐색 | **Explore** (Muse Contributor Medium) |

- Plan은 계획서 작성자나 비평 전용이 아니라 **분석 자원**입니다. 구현·승인 권한은 없습니다.
- Plan을 선택하는 것만으로 shell·브라우저·네트워크의 엄격한 읽기 전용이 보장되지는 않습니다. 비변경 보호가 필요하면 Native 세션 제한이나 실제 격리를 적용합니다.
- Sol High Build가 항상 DeepSeek Build보다 낫다는 결론은 아직 아닙니다. 완료된 비교 1건은 실제 화면 교정 3건을 찾았지만, 홈 비주얼 퍼스트와 패널/복구 카드 겹침은 남겼습니다. 모델 우위는 같은 과업의 실제 결과·추가 교정 부담·비용으로 별도 확인합니다.

## 설치

배포 정본은 `global/`입니다. 저장소를 clone/pull하는 것만으로 전역 환경이 바뀌지 않습니다.

| 저장소 | 전역 경로 | 역할 |
| --- | --- | --- |
| `global/AGENTS.md` | `~/.config/opencode/AGENTS.md` | 전 역할 공통 제품 이해·위임·수용·안전 지침 |
| `global/opencode.jsonc` | `~/.config/opencode/opencode.jsonc` | 5개 역할, 깊이 3, 모델·권한, MCP 설정 |
| `global/agents/lead.md` | `~/.config/opencode/agents/lead.md` | 배정 과업 완결 책임자 프롬프트 |

기존 설정·자격증명·다른 프로젝트·세션은 보존하고, 같은 이름의 사용자 정의와 충돌하면 확인합니다. 이전 전문 역할 파일은 자동 복원하지 않습니다. 상세 절차와 설치 요청 프롬프트는 [설치 안내](docs/installation.md)를 따릅니다.

OpenSpec 활성 통합은 퇴역했습니다. 과거 명세·변경·생성물은 [퇴역 기록](docs/archive/openspec-2026-10-26/README.md)에 보존하며, 현재 실행 의무가 아닙니다.

## 검증과 한계

하네스 검사는 **라우팅·권한·위임·지침 전달 메커니즘**을 확인합니다. 모델의 디자인 판단력이나 실제 제품 완주를 인증하지 않습니다.

```sh
# 단위·소스 계약 회귀
node --test tests/completion-guidance.test.mjs tests/capabilities.test.mjs \
  tests/session-audit.test.mjs tests/prompt-boundaries.test.mjs \
  tests/permission-probe.test.mjs tests/delegation-errors.test.mjs \
  tests/compaction-continuity.test.mjs

# 전역 설치본 5개 역할 등록·모델·권한 검사 (모델 호출 없음)
node tests/agent-routing-native.mjs

# 격리 Native 서버 위임·복구·병렬·세션 제한 통합 검사 (로컬 fixture 모델)
node tests/delegation-native-integration.mjs
```

- **현재 통과:** 회귀 **134/134**, 설치본 **146/146**, 격리 Native **362/362**.
- **Sol Build trial 1건:** 211 suites / 2,140 tests, 28개 렌더 장면, 실제 조작·axe 검증까지 수행했습니다. 캔버스 높이 초과, 공간 화면 fallback, 7px 포커스 스크롤은 스스로 찾아 고쳤습니다. 반면 홈·현장 목록의 비주얼 퍼스트와 자료 목록/복구 카드 겹침은 남겼습니다. **테스트 수가 제품 수용을 대신하지 못한 사례**입니다.
- **미입증:** 모델 간 일반 우위, 실제 픽셀·운영 데이터·고객/현장 인수, 장기 개발 완주. trial은 합성 미봉인 자료와 제한된 환경에서 수행됐고, 중간에 전역 지침이 갱신됐습니다.
